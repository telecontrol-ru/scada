## MODBUS {#modbus}

Modbus — коммуникационный протокол, основан на архитектуре ведущий-подчиненный (master-slave). Использует для передачи данных следующие интерфейсы: RS-485, RS-422, RS-232 (протоколы Modbus RTU/ASCII), а также интерфейс Ethernet сети TCP/IP (протокол Modbus TCP). ОИК поддерживает Modbus RTU и Modbus TCP; вариант Modbus ASCII в этой версии не реализован.

> ОИК использует не все функции из таблицы: 0x01, 0x02, 0x03 и 0x04 для чтения, 0x05 для записи одного дискретного выхода (Coil) и 0x10 для записи регистров хранения (Holding Registers), в том числе одного регистра. Функции 0x06 и 0x0F не используются; в режиме ретрансляции на запрос с такой функцией ОИК отвечает исключением «недопустимая функция» (ILLEGAL FUNCTION).

## МЭК-60870-5 {#iec-60870}

Элементами подсистемы МЭК-60870-5 являются направления, определяющие каналы данных: сетевой адрес или последовательный порт. Одно направление может обеспечивать соединение с несколькими устройствами.

Поддерживаемые блоки данных прикладного уровня ASDU:

| Метка типа ASDU | Идентификатор типа ASDU | Описание информации |
|:------------------|:-------------------------:|:---------------------------------------------------------------------------------------------------------:|
| M_SP_NA_1 | 1 | одноэлементная (0 – ОТКЛ, 1 – ВКЛ) | 
| M_SP_TA_1 | 2 | одноэлементная с меткой времени | 
| M_DP_NA_1 | 3 | двухэлементная (0 – Неопределенное или Промежуточное, 1 – ОТКЛ, 2 – ВКЛ, 3 – Неопределенное); смотрите примечание ниже | 
| M_BO_NA_1 | 7 | строка из 32 бит — **в этой версии не поддерживается**: значения из таких ASDU объектам не передаются | 
| M_ME_NA_1 | 9 | нормализованное значение — приходит как целое со знаком из 16 бит, смотрите примечание ниже | 
| M_ME_NB_1 | 11 | масштабированное значение (целое со знаком из 16 бит) | 
| M_ME_TB_1 | 12 | масштабированное значение (целое) с меткой времени | 
| M_ME_NC_1 | 13 | короткий формат с плавающей запятой (float) | 
| M_IT_NA_1 | 15 | интегральная сумма (int32) | 
| M_SP_TB_1 | 30 | одноэлементная с меткой времени (СР56Время2а) | 
| M_DP_TB_1 | 31 | двухэлементная с меткой времени (СР56Время2а) | 
| M_ME_TD_1 | 34 | нормализованное значение с меткой времени (СР56Время2а) — как M_ME_NA_1 | 
| M_ME_TE_1 | 35 | масштабированное значение (целое) с меткой времени (СР56Время2а) | 
| M_ME_TF_1 | 36 | короткий формат с плавающей запятой с меткой времени (СР56Время2а) | 
| M_IT_TB_1 | 37 | интегральные суммы с меткой времени (СР56Время2а) | 
| C_SC_NA_1 | 45 | одноэлементная команда управления (0 – ОТКЛЮЧИТЬ, 1 – ВКЛЮЧИТЬ) | 
| M_EI_NA_1 | 70 | конец инициализации (END OF INITIALIZATION) | 
| C_IC_NA_1 | 100 | команда полного опроса (INTERROGATION) | 
| C_CI_NA_1 | 101 | команда опроса счетчика (COUNTER INTERROGATION) | 
| C_CS_NA_1 | 103 | команда синхронизации времени (SYNCHRONIZATION) | 
| C_RP_NA_1 | 105 | команда установки процесса в исходное состояние (RESET PROCESS ACTIVATION / RESET PROCESS CONFIRMATION) | 
| P_ME_NA_1 | 110 | запись параметра измеряемой величины, нормализованное значение (целое из 16 бит) | 
| P_ME_NB_1 | 111 | запись параметра измеряемой величины, масштабированное значение (целое из 16 бит) | 
| P_ME_NC_1 | 112 | запись параметра измеряемой величины, короткий формат с плавающей запятой (float) | 

**ВНИМАНИЕ:** нормализованные значения (`M_ME_NA_1`, `M_ME_TD_1`) в этой
версии не пересчитываются в диапазон −1…+1: объект ТИТ получает целое число
из 16 бит со знаком, как оно передано (значение 1,0 приходит как 32767,
−1,0 — как −32768). Чтобы получить нормализованное значение, заведите
объект ТИТ без устройства и задайте в его поле «Канал»
[формулу]({{ '/formulas/' | relative_url }}), например
`{IEC_DEV.1!115} / 32768`, где `IEC_DEV.1` — идентификатор устройства,
а 115 — адрес информационного объекта.

Двухэлементная информация (`M_DP_NA_1`, `M_DP_TB_1`) дает объекту ТС
значение 1 только в положении 2 (ВКЛ); в положениях 0, 1 и 3 объект
получает 0. Положения 0 и 3 дополнительно отмечаются признаком качества
«Недост» (недостоверно), по которому их можно отличить от ОТКЛ.

При управлении используются ASDU `C_SC_NA_1` для объектов ТС и `P_ME_NC_1` для объектов ТИТ.

Для переопределения типа ASDU можно указать тип в поле вывода в формате `тип:адрес`

где `тип` один из:

* `BOOL` - используется ASDU `C_SC_NA_1`;
* `INT16` - используется ASDU `P_ME_NB_1`;
* `FLOAT` - используется ASDU `P_ME_NC_1`.

Переопределение типа ASDU может использоваться если для управлении объектом ТИТ требуется отправить команду управления ASDU `C_SC_NA_1`.

Сервер UDP позволяет одновременную работу с несколькими удаленными устройствам через одно направление, так что нет необходимости задавать разные порты приема для разных устройств. Устройство идентифицируется по удаленному IP-адресу и порту.

При использовании сервера UDP поддерживаются устройства, отправляющие датаграммы из нескольких сообщений МЭК.

Смотрите параметры [Устройства МЭК-60870-5]({{ '/dev/devices/' | relative_url }}#iecDevice) в Клиенте ОИК.

Смотрите описание протоколов [МЭК-60870-5](https://ru.wikipedia.org/wiki/IEC_60870-5).

## МЭК-61850 {#iec-61850}

Предоставляется прозрачный доступ к информационной модели устройства. Смотрите описание [МЭК-61850]({{ '/client/' | relative_url }}#iec-61850) в Клиенте ОИК и [Проектирование]({{ '/dev/devices/' | relative_url }}#iec-61850).

Сбор данных осуществляется только посредством подписки на блоки управления
отчетами (RCB — небуферизованные, BRCB — буферизованные) сервиса MMS. Сервер
ОИК не читает значения напрямую: объект, данные которого не входят ни в один
подписанный отчет, значений не получает. Чтобы включить сбор данных:

1. Под устройством МЭК-61850 в окне «Оборудование» создайте командой
   *Создать — RCB МЭК-61850* блок управления отчетами и укажите в его поле
   «Адрес» MMS-адрес блока в модели устройства: логическое устройство,
   логический узел (обычно `LLN0`), функциональную связь `RP`
   (небуферизованный) или `BR` (буферизованный) и имя блока, например
   `LD0/LLN0$RP$urcbA01` или `LD0/LLN0$BR$brcbA01`. Имя блока и состав его
   набора данных (DataSet) определяются конфигурацией устройства.
2. Привяжите объекты ТС и ТИТ к элементам набора данных этого блока. Адрес
   в поле «Канал» объекта должен **в точности** совпадать с элементом
   набора данных, включая регистр букв и уровень вложенности: элемент
   `LD0/GGIO1$ST$Ind1` и адрес `LD0/GGIO1$ST$Ind1$stVal` — разные адреса,
   и значение по такому адресу не придет. Перетаскивание объекта из поддерева
   «Модель» записывает адрес в правильном виде; проверьте только, что этот
   объект входит в набор данных блока.

При установлении соединения Сервер ОИК читает у устройства параметры блока и
состав его набора данных, включает отчеты и запрашивает общий опрос (GI)
через блок: устройство, поддерживающее GI, сразу присылает текущие значения
всех элементов набора, а затем — спорадические отчеты об изменениях.
Сообщения о подписке на блок и составе его набора данных видны в окне
[Наблюдение]({{ '/client/device-watch/' | relative_url }}).

Для привязки объектов ТС и ТИТ к объектам МЭК-61850 используются адреса MMS в
формате `LogicalDevice/LogicalNode$FC$DataObject`. Для привязки объектов ТС
используются объекты типа FC=ST, для привязки объектов ТИТ — объекты типа
FC=MX.

**ВНИМАНИЕ:** в этой версии правильно читаются только:

* одноэлементные состояния (класс SPS, логическое значение `stVal`) — для
  объектов ТС;
* измерения FC=MX со значением с плавающей запятой (`mag.f`, например класс
  MV) — для объектов ТИТ.

Двухэлементные положения (классы DPS и DPC, например `Pos`, тип Dbpos)
читаются неверно: объект ТС показывает постоянно состояние «включено» при
привязке к объекту данных или не получает значения при привязке к `stVal`.
Не используйте такие объекты для отображения положения коммутационных
аппаратов; если это необходимо, обратитесь в ООО «Телеконтроль»
(mail@telecontrol.ru).

**ВНИМАНИЕ:** в этой версии для устройств МЭК-61850 не работают
телеуправление (ТУ, FC=CO) и команда «Опрос устройства»: Сервер отклоняет
их с ошибкой. Управлять коммутационными аппаратами через устройство
МЭК-61850 в этой версии нельзя.

**ВНИМАНИЕ:** поддерживается передача меток времени только в UTC. Если
устройство использует другую временную зону, возникнут сложности с
обновлением значений.

Смотрите описание протоколов [МЭК-61850](https://ru.wikipedia.org/wiki/МЭК-61850).
