## MODBUS {#modbus}

Modbus — коммуникационный протокол, основан на архитектуре ведущий-подчиненный (master-slave). Использует для передачи данных следующие интерфейсы: RS-485, RS-422, RS-232 (протоколы Modbus RTU/ASCII), а также интерфейс Ethernet сети TCP/IP (протокол Modbus TCP). ОИК поддерживает все три варианта: Modbus RTU, Modbus ASCII и Modbus TCP.

![]({{ '/img/MODBUS_func.png' | relative_url }})

{: .note }
> ОИК использует не все функции из таблицы: 0x01, 0x02, 0x03 и 0x04 для чтения, 0x05 для записи одного дискретного выхода (Coil) и 0x10 для записи регистров хранения (Holding Registers), в том числе одного регистра. При опросе функции 0x06 и 0x0F не используются. В режиме ретрансляции ОИК принимает запись функциями 0x05, 0x06, 0x0F и 0x10, а на запрос с другой функцией отвечает исключением «недопустимая функция» (ILLEGAL FUNCTION).

## МЭК-60870-5 {#iec-60870}

Элементами подсистемы МЭК-60870-5 являются направления, определяющие каналы данных: сетевой адрес или последовательный порт. Одно направление может обеспечивать соединение с несколькими устройствами.

Поддерживаемые блоки данных прикладного уровня ASDU:

| Метка типа ASDU | Идентификатор типа ASDU | Описание информации |
|:------------------|:-------------------------:|:---------------------------------------------------------------------------------------------------------:|
| M_SP_NA_1 | 1 | одноэлементная (0 – ОТКЛ, 1 – ВКЛ) | 
| M_SP_TA_1 | 2 | одноэлементная с меткой времени | 
| M_DP_NA_1 | 3 | двухэлементная (0 – Неопределенное или Промежуточное, 1 – ОТКЛ, 2 – ВКЛ, 3 – Неопределенное); смотрите примечание ниже | 
| M_BO_NA_1 | 7 | строка из 32 бит — объект ТИТ получает целое число без знака, в котором бит 1 строки — младший | 
| M_ME_NA_1 | 9 | нормализованное значение — пересчитывается в диапазон −1…+1, смотрите примечание ниже | 
| M_ME_NB_1 | 11 | масштабированное значение (целое со знаком из 16 бит) | 
| M_ME_TB_1 | 12 | масштабированное значение (целое) с меткой времени | 
| M_ME_NC_1 | 13 | короткий формат с плавающей запятой (float) | 
| M_IT_NA_1 | 15 | интегральная сумма (int32) | 
| M_SP_TB_1 | 30 | одноэлементная с меткой времени (СР56Время2а) | 
| M_DP_TB_1 | 31 | двухэлементная с меткой времени (СР56Время2а) | 
| M_BO_TB_1 | 33 | строка из 32 бит с меткой времени (СР56Время2а) — как M_BO_NA_1 | 
| M_ME_TD_1 | 34 | нормализованное значение с меткой времени (СР56Время2а) — как M_ME_NA_1 | 
| M_ME_TE_1 | 35 | масштабированное значение (целое) с меткой времени (СР56Время2а) | 
| M_ME_TF_1 | 36 | короткий формат с плавающей запятой с меткой времени (СР56Время2а) | 
| M_IT_TB_1 | 37 | интегральные суммы с меткой времени (СР56Время2а) | 
| C_SC_NA_1 | 45 | одноэлементная команда управления (0 – ОТКЛЮЧИТЬ, 1 – ВКЛЮЧИТЬ) | 
| M_EI_NA_1 | 70 | конец инициализации (END OF INITIALIZATION) | 
| C_IC_NA_1 | 100 | команда полного опроса (INTERROGATION) | 
| C_CI_NA_1 | 101 | команда опроса счетчика (COUNTER INTERROGATION) | 
| C_CS_NA_1 | 103 | команда синхронизации времени (SYNCHRONIZATION) | 
| C_RP_NA_1 | 105 | команда установки процесса в исходное состояние (RESET PROCESS ACTIVATION / RESET PROCESS CONFIRMATION) | 
| P_ME_NA_1 | 110 | запись параметра измеряемой величины, нормализованное значение (−1…+1) | 
| P_ME_NB_1 | 111 | запись параметра измеряемой величины, масштабированное значение (целое из 16 бит) | 
| P_ME_NC_1 | 112 | запись параметра измеряемой величины, короткий формат с плавающей запятой (float) | 

Нормализованные значения (`M_ME_NA_1`, `M_ME_TD_1`, `P_ME_NA_1`)
пересчитываются в диапазон −1…+1: переданное устройством целое число из 16 бит
делится на 32768, поэтому объект ТИТ получает, например, 0,5 вместо 16384.
Наибольшее значение — 32767/32768 ≈ 0,99997; ровно +1,0 этим типом не
передается. При ретрансляции такое значение передается дальше без потерь.

{: .note }
> В предыдущих версиях объект ТИТ получал нормализованное значение как целое
> число (32767 вместо 1,0). Если в проекте значение пересчитывалось
> формулой, например `{IEC_DEV.1!115} / 32768`, или линейным преобразованием
> из диапазона −32768…32767, после обновления уберите этот пересчет — иначе
> значение будет поделено дважды.

Двухэлементная информация (`M_DP_NA_1`, `M_DP_TB_1`) дает объекту ТС
значение 1 только в положении 2 (ВКЛ); в положениях 0, 1 и 3 объект
получает 0. Положения 0 и 3 дополнительно отмечаются признаком качества
«Недост» (недостоверно), по которому их можно отличить от ОТКЛ.

При управлении используются ASDU `C_SC_NA_1` для объектов ТС и `P_ME_NC_1` для объектов ТИТ.

При [двухэтапном управлении]({{ '/dev/data-items/' | relative_url }}) объекта ТС
команда `C_SC_NA_1` сначала посылается с признаком выбора (S/E = 1), затем —
с признаком исполнения. Если оператор отказывается от исполнения, Сервер
снимает выбор: повторяет ту же команду с причиной передачи 8 (деактивация) и
ждет от устройства подтверждения с причиной передачи 9. Если устройство
отказалось снять выбор, он остается в силе до истечения таймаута выбора самого
устройства, и Клиент сообщает об этом в панели текущих событий.

В режиме ретрансляции Сервер сам принимает команды ДЦ. Если ДЦ снимает выбор
объекта (команда с причиной передачи 8 после подтвержденного выбора), Сервер
снимает выбор на исходном устройстве объекта тем же способом и подтверждает
деактивацию ДЦ причиной передачи 9 только после ответа исходного устройства;
если устройство отказалось снять выбор, подтверждение отрицательное. Источник,
у которого нет выбора (например, объект устройства MODBUS), подтверждает снятие
выбора сразу. Деактивация уже исполняемой команды только прекращает ответ ДЦ:
отменить исполнение на устройстве нельзя.

Для переопределения типа ASDU можно указать тип в поле вывода в формате `тип:адрес`

где `тип` один из:

* `BOOL` - используется ASDU `C_SC_NA_1`;
* `INT16` - используется ASDU `P_ME_NB_1`;
* `FLOAT` - используется ASDU `P_ME_NC_1`.

Переопределение типа ASDU может использоваться если для управлении объектом ТИТ требуется отправить команду управления ASDU `C_SC_NA_1`.

Сервер UDP позволяет одновременную работу с несколькими удаленными устройствам через одно направление, так что нет необходимости задавать разные порты приема для разных устройств. Устройство идентифицируется по удаленному IP-адресу и порту.

При использовании сервера UDP поддерживаются устройства, отправляющие датаграммы из нескольких сообщений МЭК.

Смотрите параметры [Устройства МЭК-60870-5]({{ '/dev/devices/' | relative_url }}#iecDevice) в Клиенте ОИК.

Смотрите описание протоколов [МЭК-60870-5](https://ru.wikipedia.org/wiki/IEC_60870-5).

## МЭК-61850 {#iec-61850}

Предоставляется прозрачный доступ к информационной модели устройства. Смотрите описание [МЭК-61850]({{ '/client/' | relative_url }}#iec-61850) в Клиенте ОИК и [Проектирование]({{ '/dev/devices/' | relative_url }}#iec-61850).

Сбор данных осуществляется только посредством подписки на блоки управления
отчетами (RCB — небуферизованные, BRCB — буферизованные) сервиса MMS. Сервер
ОИК не читает значения напрямую: объект, данные которого не входят ни в один
подписанный отчет, значений не получает. Чтобы включить сбор данных:

1. Под устройством МЭК-61850 в окне «Оборудование» создайте командой
   *Создать — RCB МЭК-61850* блок управления отчетами и укажите в его поле
   «Адрес» MMS-адрес блока в модели устройства: логическое устройство,
   логический узел (обычно `LLN0`), функциональную связь `RP`
   (небуферизованный) или `BR` (буферизованный) и имя блока, например
   `LD0/LLN0$RP$urcbA01` или `LD0/LLN0$BR$brcbA01`. Имя блока и состав его
   набора данных (DataSet) определяются конфигурацией устройства.
2. Привяжите объекты ТС и ТИТ к элементам набора данных этого блока. Адрес
   в поле «Канал» объекта должен **в точности** совпадать с элементом
   набора данных, включая регистр букв и уровень вложенности: элемент
   `LD0/GGIO1$ST$Ind1` и адрес `LD0/GGIO1$ST$Ind1$stVal` — разные адреса,
   и значение по такому адресу не придет. Перетаскивание объекта из поддерева
   «Модель» записывает адрес в правильном виде; проверьте только, что этот
   объект входит в набор данных блока.

При установлении соединения Сервер ОИК читает у устройства параметры блока и
состав его набора данных, включает отчеты и запрашивает общий опрос (GI)
через блок: устройство, поддерживающее GI, сразу присылает текущие значения
всех элементов набора, а затем — спорадические отчеты об изменениях.
Сообщения о подписке на блок и составе его набора данных видны в окне
[Наблюдение]({{ '/client/device-watch/' | relative_url }}).

Блоки RCB можно создавать, изменять и удалять в любой момент, в том числе
у включенного устройства: Сервер переподписывается на блок без перезапуска
процесса. «Адрес» блока должен содержать функциональную связь `RP` или `BR`;
блок с другой функциональной связью Сервер не подписывает и сообщает об этом
в окне «Наблюдение».

Для привязки объектов ТС и ТИТ к объектам МЭК-61850 используются адреса MMS в
формате `LogicalDevice/LogicalNode$FC$DataObject`. Для привязки объектов ТС
используются объекты типа FC=ST, для привязки объектов ТИТ — объекты типа
FC=MX.

Значения читаются так:

* состояния FC=ST с логическим значением `stVal` (классы SPS, SPC) — как
  «включено»/«отключено»;
* двухэлементные положения (классы DPS и DPC, например `Pos`, тип Dbpos) —
  объект ТС показывает «включено» только в положении «включено»;
  промежуточное и неисправное положения показываются как «отключено», как и
  для двухэлементной информации МЭК-60870-5. Привязывать объект можно и к
  объекту данных (`LD0/XCBR1$ST$Pos`), и к атрибуту `stVal`
  (`LD0/XCBR1$ST$Pos$stVal`) — в зависимости от того, что входит в набор
  данных блока;
* целочисленные состояния (например, классы INS, INC) — как число;
* измерения FC=MX со значением с плавающей запятой (`mag.f`, например класс
  MV) — для объектов ТИТ.

Телеуправление (ТУ) выдается на управляемый объект данных (классы SPC, DPC,
INC, APC, BSC). В адресе управления объекта можно указать объект данных в
функциональной связи CO или ST — `LD0/CSWI1$CO$Pos`,
`LD0/CSWI1$ST$Pos` или `LD0/CSWI1$ST$Pos$stVal`: во всех случаях команда
адресуется объекту данных `Pos`. Модель управления (`ctlModel`) и тип
значения команды Сервер читает из устройства:

* для устройства с выбором перед исполнением (SBO, `sbo-with-normal-security`
  или `sbo-with-enhanced-security`) оставьте у объекта
  [Двухэтапное управление]({{ '/dev/data-items/' | relative_url }})
  включенным (по умолчанию «Да») — без этапа выбора устройство отклонит
  команду. Если оператор отказывается от исполнения, Сервер снимает выбор
  службой Cancel модели управления;
* для прямого управления (`direct-with-normal-security`,
  `direct-with-enhanced-security`) подходит и одноэтапная, и двухэтапная
  команда;
* объект с моделью `status-only` команд не принимает — Сервер отклоняет их.

Значение команды должно соответствовать типу `ctlVal` объекта:

* 0 или 1 для логического значения (SPC, DPC);
* целое число для INC;
* число для уставки с аналоговым значением (APC). Сервер читает из модели
  устройства, задается ли уставка целым числом (`i`) или числом с
  плавающей запятой (`f`); для целочисленной уставки дробное значение не
  подходит. Уставку, у которой в модели устройства заданы оба поля, `i` и
  `f`, Сервер не выдает: целое поле масштабируется настройками самого
  объекта (`sVC`);
* для пошагового управления (BSC, например переключатель отпаек
  трансформатора) — номер команды: 1 — шаг вниз (lower), 2 — шаг вверх
  (higher), 0 — стоп (stop). Логическое значение «включить»/«отключить»
  такому объекту не подходит; используйте ТУ с вводом значения.

Иное значение Сервер отклоняет, не отправляя на устройство. Выбор и снятие
выбора (Cancel) для APC и BSC работают так же, как для SPC и DPC.

Если устройство отклонило выбор или исполнение команды (например, по
собственной блокировке или из-за несовпадения модели управления), Клиент
сообщает «Ошибка протокола МЭК-61850»; ответ устройства виден в окне
[Наблюдение]({{ '/client/device-watch/' | relative_url }}).

Команда «Опрос устройства» запрашивает общий опрос (GI) через все блоки RCB
устройства.

Метки времени МЭК-61850 по стандарту всегда передаются в UTC: в протоколе
нет поля временной зоны, и Сервер не пересчитывает метки. Поэтому часы
устройства должны идти по UTC — обычно их синхронизирует SNTP. Если часы
устройства выставлены по местному времени, метки значений и событий будут
смещены на разницу с UTC; исправьте это в настройках устройства. Метки
времени устройств первой редакции стандарта (тип BinaryTime) также
поддерживаются.

Устройство МЭК-61850 не может быть приемником
[ретрансляции]({{ '/dev/devices/' | relative_url }}#retransmission): процесс
МЭК-61850 только опрашивает устройства.

Смотрите описание протоколов [МЭК-61850](https://ru.wikipedia.org/wiki/МЭК-61850).
