# Конфигурирование пользователей
{:.no_toc}

* TOC
{:toc}

Окно пользователей открывается командой главного меню *Дополнительно —
Пользователи* или кнопкой «Пользователи» внизу панели разделов. Окно доступно
только учётной записи с правом «Настройка конфигурации» (роль
`ConfigureAdmin`).

![]({{ '/img/users.png' | relative_url }})

Двойной щелчок в строке пользователя позволяет начать редактирование его
свойств: имени, описания и прав. Свойство «Права» в этой версии ничего
не разрешает — смотрите [Права доступа](#access-rights).

Для создания нового пользователя выберите команду *Создать - Пользователь* из контекстного меню окна.

Для удаления пользователя выберите команду *Удалить* из контекстного меню пользователя.

Для смены пароля выберите команду *Задать пароль* из контекстного меню
пользователя. Своя учётная запись требует ввода текущего пароля, чужая (сброс
администратором) — нет. Требования к паролю задаёт Сервер; смотрите
[Политика паролей]({{ '/client/workbench/' | relative_url }}#password-policy).

**Администратору:**

* **Никогда не изменяйте и не удаляйте пользователя `svc`.** Это служебная
  учетная запись, через которую процессы Сервера подключаются друг к другу;
  после ее изменения связи между ними перестают работать (смотрите
  [Учетная запись svc]({{ '/server/' | relative_url }}#svc)).
* **Пользователь `root` в списке новой установки — не встроенная учетная
  запись `root`.** Он входит в демонстрационный проект и войти не может
  никогда: вход под именем `root` всегда выполняется встроенной учетной
  записью. Изменение или удаление этого пользователя на нее не влияет.
* **Пароль `root`, заданный в этом окне, не сохраняется.** Каждый процесс
  Сервера при каждом запуске снова записывает пароль, заданный в
  `scada-setup apply` параметром `--root-password`. Меняйте пароль `root`
  через `scada-setup` (смотрите
  [Пароль root]({{ '/getting-started/' | relative_url }}#пароль-root)).
* **Встроенная учетная запись `root` допускает только один сеанс.** При
  повторном входе под `root`, например с другого рабочего места, Клиент
  сообщает, что имя пользователя уже используется, и предлагает отключить
  открытый сеанс; при согласии первый сеанс `root` отключается. Заведите
  каждому администратору своего пользователя, а не входите всем под `root`.

## Права доступа {#access-rights}

Что разрешено учётной записи после входа, Сервер определяет по **ролям** OPC
UA, в которые она включена. Права дают две роли:

<dl>

<dt>Operator — право «Управление»</dt>
<dd>Выдача команд телеуправления и телерегулирования, ручной ввод, задание
уставок.</dd>

<dt>ConfigureAdmin — право «Настройка конфигурации»</dt>
<dd>Создание, изменение и удаление объектов, устройств и учётных записей.
Команд управления, ручного ввода и изменения уставок это право не дает.</dd>

</dl>

Их сочетания дают привычные четыре уровня:

| Уровень | Роли учётной записи | Управление, ручной ввод, уставки | Редактирование конфигурации |
|:-----------------------|:---|:----------:|:---:|
| 0 (Руководитель) | нет | НЕТ | НЕТ |
| 1 (Инженер АСУ и связи) | `ConfigureAdmin` | НЕТ | ДА |
| 2 (Диспетчер) | `Operator` | ДА | НЕТ |
| 3 (Администратор) | `Operator` и `ConfigureAdmin` | ДА | ДА |

Команды телеуправления и телерегулирования, ручной ввод и изменение уставок
доступны только с правом «Управление». Уставки объекта ТИТ показаны и в его
свойствах (группа «Уставки» окна «Свойства»), но без права «Управление» они там
доступны только для чтения. При вставке скопированного объекта ТИТ
пользователем без этого права уставки не переносятся: объект создается без
них.

Конфигурацию, наоборот, изменяет только право «Настройка конфигурации».
Единственное исключение — команды *Включить* и *Отключить* устройства: вывести
устройство из работы и вернуть его можно и с одним правом «Управление».

**ВНИМАНИЕ: в этой версии свойство «Права» учётной записи ничего не
разрешает.** Его значение (0–3) по-прежнему можно ввести, но при входе Сервер
выдает права только по ролям. Пользователь, созданный в Клиенте с
«Права» = 3, после входа может только просматривать данные: в колонке «Роли»
окна «Пользователи» у него указано «Нет». Включить новую учётную запись в роль
`Operator` или `ConfigureAdmin` средствами Клиента в этой версии нельзя — окно
«Роли» доступно только для чтения, а программа установки `scada-setup` роли не
назначает. Если новому пользователю нужны права управления или настройки,
обратитесь в ООО «Телеконтроль» (mail@telecontrol.ru) заранее, до ввода
объекта в эксплуатацию.

Учётные записи, существовавшие до обновления на эту версию, в том числе
перенесённые из версии 2.5, свои права сохраняют: при первом запуске Сервер
один раз переводит их значение «Права» в членство в ролях `Operator` и
`ConfigureAdmin`. Учётная запись `root` сохраняет все права независимо от
ролей.

## Роли {#roles}

Роли, которые Сервер выдает сессии:

* любая учётная запись, вошедшая в систему, получает роль `Observer` — чтение
  значений, истории и событий;
* роль `Operator` — запись значений и вызов методов, в том числе команд
  управления, ручного ввода и изменения уставок; конфигурацию эта роль не
  изменяет, кроме включения и отключения устройств;
* роль `ConfigureAdmin` добавляет к сессии также роли `Engineer`,
  `Supervisor` и `SecurityAdmin` — изменение конфигурации, включая создание и
  удаление узлов, но не запись значений объектов, не их уставки и не команды
  управления: эти действия Сервер разрешает только роли `Operator`;
* анонимная сессия получает только роль `Anonymous`.

Учётная запись может нести несколько ролей одновременно, и их разрешения
объединяются. Именно роли показаны в окне
[«Пользователи»]({{ '/client/workbench/' | relative_url }}#users) и в панели «Права доступа»
рабочего места; там же по ролям выводится, что учётной записи разрешено
просматривать, чем управлять и что настраивать.

Состав ролей можно посмотреть в окне [«Роли»]({{ '/client/workbench/' | relative_url }}#roles). Оно
доступно только для чтения: изменение состава роли — привилегированная
операция, выполняемая на Сервере.

Все действия с учётными записями, паролями и составом ролей — и удавшиеся, и
отклонённые — записываются в [журнал аудита]({{ '/client/workbench/' | relative_url }}#audit-log).
