# Начало работы
{:.no_toc}

* TOC
{:toc}

Эта страница описывает версию 2.6, в которой Сервер состоит из отдельных
процессов (смотрите [Состав Сервера]({{ '/architecture/' | relative_url }}#tiers)).

## Системные требования

* Сервер: ОС Windows 10 и выше или Linux x86-64 с systemd и glibc 2.38 и
  выше, например Ubuntu 24.04 (смотрите [Установка под Linux](#linux))
* Клиент: ОС Windows 10 и выше (x64) или macOS на компьютере с процессором
  Apple — наименьшая версия macOS указана в описании выпуска (смотрите [Установка Клиента](#client-install)); Клиента для Linux нет
* Права администратора Windows (под Linux — `root`) для установки и
  настройки Сервера
* Сеть TCP/IP между компьютерами объекта; Клиенты подключаются к процессу
  `scada-proxy` по порту 2000 (смотрите [Настройка сети](#network))
* Файл лицензии, выданный на нужные процессы Сервера (смотрите [Лицензия](#license))

## Выбор процессов Сервера {#choose}

Сервер версии 2.6 всегда устанавливается из нескольких процессов: процессы
протокольного уровня получают конфигурацию от `scada-config` и не хранят ее
сами, поэтому один такой процесс без `scada-config` работать не может.

Наименьший набор, который создает `scada-setup`:

* `scada-config` — хранит конфигурацию;
* один или несколько процессов протокольного уровня (`scada-modbus`,
  `scada-iec104`, `scada-iec61850`, на Windows также `scada-opc` и
  `scada-vidicon`);
* `scada-filesystem` — без него `scada-setup apply` выводит предупреждение, и
  [серверная файловая система]({{ '/server/' | relative_url }}#filesystem)
  (мнемосхемы на Сервере) недоступна;
* `scada-proxy` — к нему подключаются Клиенты.

Для архива значений и событий добавьте `scada-historian`; без него архива нет.

**Лицензия должна называть каждый из этих процессов**, в том числе
`config`, `filesystem` и `proxy`, а не только процессы протокольного уровня:
процесс, которого нет в лицензии, останавливается сразу после запуска, а
`scada-setup apply` отказывается его устанавливать.

Все процессы можно установить на один компьютер или распределить по
нескольким. **`scada-config`, `scada-proxy`, `scada-historian` и
`scada-filesystem` всегда устанавливаются на один и тот же компьютер —
центральный**; процессы протокольного уровня — на него же или на другие
компьютеры объекта. Назначение каждого процесса и порядок запуска описаны
в разделе [Состав Сервера]({{ '/architecture/' | relative_url }}#tiers).

Разные процессы протокольного уровня можно поставить на разные компьютеры
(например, `scada-modbus` на один, `scada-iec104` на другой). **Один и тот же
процесс протокольного уровня тоже можно установить на несколько компьютеров**
и разделить между ними устройства своего протокола — например, поставить
`scada-iec104` рядом с каждой группой устройств:

* какой компьютер обслуживает направление, задает свойство направления
  «Компьютер» (у устройства МЭК-61850, у которого направлений нет, — свойство
  самого устройства): имя компьютера, которое `scada-setup` записывает в его
  файлы параметров, — имя компьютера Windows или значение `--host-name`;
  регистр букв не важен;
* устройства направления обслуживает тот же компьютер, что и направление;
* направления с пустым свойством «Компьютер» обслуживает компьютер,
  на котором `scada-setup apply` выполнен **без** параметра
  `--assigned-links-only`. На остальных компьютерах с этим процессом
  выполните `apply` с `--assigned-links-only`: такой компьютер обслуживает
  только направления, назначенные ему по имени;
* чтобы перенести направление на другой компьютер, измените его свойство
  «Компьютер» в Клиенте: прежний компьютер закрывает связь, новый открывает
  ее, перезапускать процессы не нужно.

Клиенты, архив и ретрансляция работают с устройствами всех компьютеров
через `scada-proxy` как с одним Сервером.

**ВНИМАНИЕ:** на компьютерах одного протокольного процесса параметр
`--assigned-links-only` должен быть задан на всех, кроме одного. Если его
нет ни на одном из двух компьютеров, оба откроют каждое направление без
компьютера; если он есть на всех, такие направления не обслуживает никто.

## Установка под Windows

Установщик Сервера задуман одним для всех процессов Сервера и программы
настройки `scada-setup`; для версии 2.6 он еще не опубликован (смотрите
[Загрузка](#download)). Какие процессы будут работать на компьютере, задаете вы
параметром `--tiers`; лицензия определяет, какие из них разрешены.

**Запускайте `scada-setup` из командной строки с правами администратора**
(команде `status` они не нужны). Установщик не добавляет папку программы в
переменную `PATH`, поэтому в примерах она вызывается по полному пути
`"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe"`; из этой папки
достаточно набрать `scada-setup`.

1. Установите пакет:

   ```bat
   msiexec /i telecontrol-scada-<версия>.msi /qn /norestart /l*v install.log
   ```

   Ключ `/qn` устанавливает пакет без окон, `/norestart` не дает установщику
   Windows самому перезагрузить компьютер, `/l*v install.log` записывает
   подробный журнал установки в файл `install.log` — по нему разбирают
   ошибки установки (это общие ключи установщика Windows).

2. Поместите файл лицензии в
   `%ProgramData%\Telecontrol\SCADA Server\license.json`.

3. Решите, какие процессы будут работать на этом компьютере, и
   [запишите параметры компьютера](#host-parameters).

4. Выполните:

   ```bat
   "C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" apply --tiers config,historian,filesystem,iec104,proxy --svc-password <пароль> --root-password <пароль root>
   ```

   В `--tiers` перечислите процессы этого компьютера (в примере — все
   процессы на одном компьютере с протоколом МЭК 60870-5-104). `<пароль>` —
   пароль служебной учетной записи `svc`, через которую процессы подключаются
   друг к другу. Он должен быть одинаковым на всех компьютерах объекта;
   сменить его потом можно только командой `scada-setup set-password` на
   каждом компьютере (смотрите
   [Учетная запись svc]({{ '/server/' | relative_url }}#svc)).
   `<пароль root>` — пароль встроенной учетной записи `root`, смотрите
   [Пароль root](#пароль-root).

Команда `apply` создает для каждого процесса файл параметров
`%ProgramData%\Telecontrol\SCADA Server\<процесс>\server.json` (у
`scada-filesystem` папка называется `filestore`), создает
[сертификат Сервера]({{ '/server/' | relative_url }}#opcua-certificate) в
`C:\Program Files\Telecontrol SCADA\data\Certificates`, если его там еще нет,
создает конфигурационные БД с пустым проектом (с ключом `--demo` — с
демонстрационным, смотрите [Подготовка проекта](#project); существующие БД
не перезаписываются; в БД `scada-filesystem` остается только служебная
учетная запись `svc`), регистрирует
по службе Windows на процесс и запускает их в нужном порядке. Проверить
результат:

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" status
```

В сообщениях `scada-setup` процессы называются *tiers*: строка
`Entitled tiers: …` перечисляет процессы, разрешенные лицензией, а под ней
для каждого процесса выводится состояние его службы (`SERVICE_RUNNING` —
работает).

**ВНИМАНИЕ: пароли `svc` и `root` может прочитать администратор этого
компьютера.** `apply` сохраняет их в зашифрованном файле, который открывают
только службы Сервера и администраторы (смотрите
[Где хранятся пароли]({{ '/server/' | relative_url }}#stored-passwords)).
Не давайте посторонним прав администратора на компьютерах Сервера и не
делайте компьютер Сервера рабочим местом операторов. Установщик Сервера
ставит на компьютер и Клиент (смотрите [Установка Клиента](#client-install)).

**Несколько компьютеров.** Сначала настройте центральный компьютер. Его
`apply` выводит строку с отпечатком его сертификата (позже ее можно увидеть
снова командой `scada-setup status` на центральном компьютере):

```
Links are encrypted (SignAndEncrypt). Join the other computers of the site with
  --central-fingerprint 30:CE:C4:DB:...:66:6F
('scada-setup status' prints it again)
```

Затем настройте компьютеры с процессами протокольного уровня, указав каждому
адрес центрального компьютера и этот отпечаток:

```bat
rem Центральный компьютер:
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" apply --tiers config,historian,filesystem,proxy --advertise 10.0.0.10 --svc-password <пароль> --root-password <пароль root>
rem Компьютер с процессами протокольного уровня:
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" apply --tiers modbus,iec104 --central 10.0.0.10 --central-fingerprint 30:CE:C4:DB:...:66:6F --advertise 10.0.0.11 --svc-password <пароль>
```

Процессам протокольного уровня пароль `root` не нужен: учетные записи для них
хранит `scada-config`. На компьютере без `scada-config` параметр `--central`
обязателен. С `--central-fingerprint` компьютер получает сертификат от
удостоверяющего центра объекта на центральном компьютере, и его процессы
подключаются к остальным с шифрованием. **Без него процессы этого компьютера
к остальным вообще не подключаются**: остальные процессы не принимают
соединения без шифрования и сертификаты, выданные не удостоверяющим центром
объекта. Поэтому `apply` с `--central` без `--central-fingerprint` и без
`--insecure-links` завершается ошибкой и ничего не меняет (смотрите
[Удостоверяющий центр объекта]({{ '/server/' | relative_url }}#opcua-site-ca)).
Без шифрования работает только объект, все компьютеры которого настроены с
параметром `--insecure-links`.
`--advertise` центрального компьютера — это адрес, который остальные
компьютеры указывают в `--central`.

**Решите вопрос с `--advertise` до первого `apply` на каждом компьютере с
процессами протокольного уровня.** Компьютер, настроенный с `--central`,
сообщает `scada-proxy` свое *имя компьютера*, и `scada-proxy` подключается к
его процессам по этому имени. Если центральный компьютер не разрешает имена
всех компьютеров с процессами протокольного уровня (проверьте командой
`ping <имя компьютера>` на центральном компьютере), укажите каждому из них
его собственный адрес IP в `--advertise`, как в примере (10.0.0.11 — адрес
самого компьютера с процессами протокольного уровня). Иначе устройства этого
компьютера так и не появятся в Клиенте.
[Сертификат Сервера]({{ '/server/' | relative_url }}#opcua-certificate)
запоминает адреса компьютера только при создании: если вы добавите
`--advertise` позже, замените и сертификат, чтобы в нем был новый адрес.

Остальные связи между процессами настраиваются автоматически.
Все команды `scada-setup` описаны в разделе
[Сервер]({{ '/server/' | relative_url }}#scada-setup).

Как установить Клиент на рабочие места операторов, описано ниже, в разделе
[Установка Клиента](#client-install).

### Параметры компьютера {#host-parameters}

`scada-setup` не запоминает, с какими параметрами его запускали. **Запишите
для каждого компьютера** и храните вместе с паролями:

* `--tiers` — процессы этого компьютера;
* `--central` — адрес центрального компьютера (на компьютере без
  `scada-config`);
* `--advertise` — если вы его задавали;
* `--central-fingerprint` — отпечаток сертификата центрального компьютера (на
  компьютере без `scada-config`);
* `--assigned-links-only` — если вы его задавали;
* `--host-name` — если вы его задавали;
* `--insecure-links` — если объект настроен без шифрования;
* `--allow-anonymous-opcua` — если вы его задавали (на компьютере с
  `scada-proxy`);
* `--license` — если файл лицензии лежит не в
  `%ProgramData%\Telecontrol\SCADA Server\license.json`;
* `--data-root` — если вы задавали папку данных не стандартную;
* пароль `svc` и пароль `root`.

**Указывайте эти параметры в каждой команде `apply` и `start`** на этом
компьютере (в `apply` — также пароли), в том числе при обновлении и
восстановлении:

* без `--tiers` обе команды берут **все** процессы из лицензии: `apply`
  устанавливает на компьютер процессы, которых на нем быть не должно, а
  `start` запускает только те из них, службы которых есть на компьютере, и
  про остальные выводит `Skipped <процесс>: not installed on this host`; если
  на компьютере нет ни одной из этих служб, `start` завершается с ошибкой;
* без `--central` на компьютере без `scada-config` `apply` отказывается
  работать (`start` этот параметр не нужен);
* `apply` без `--assigned-links-only` на компьютере, где он был задан,
  делает этот компьютер обслуживающим направления без компьютера, и два
  компьютера открывают одни и те же направления;
* `apply` без `--host-name` на компьютере, где он был задан, записывает имя
  компьютера Windows, и направления, назначенные прежнему имени, компьютер
  больше не обслуживает;
* на объекте без шифрования `apply` без `--insecure-links` на центральном
  компьютере создает удостоверяющий центр, и остальные компьютеры перестают
  с ним связываться, пока их не подключат заново с `--central-fingerprint`;
* без `--license` команды ищут лицензию в
  `%ProgramData%\Telecontrol\SCADA Server\license.json`, а `apply`
  записывает этот путь в файлы параметров (но не в службы);
* `--license` указывайте полным путем, начиная с буквы диска: `scada-setup`
  передает путь процессам так, как он записан, и относительный путь не
  приведет их к тому же файлу.

Команды `stop`, `status` и `remove` без `--tiers` действуют на все службы
Сервера, которые есть на компьютере, поэтому `--tiers` и `--central` им
указывать не нужно. Но `status` проверяет лицензию по пути
`<папка данных>\license.json` (по умолчанию
`%ProgramData%\Telecontrol\SCADA Server\license.json`): если файл лицензии
лежит в другом месте, укажите ему `--license` (и `--data-root`, если папка
данных не стандартная), иначе он выведет `License: not available` вместо
сведений о лицензии.

**Если `apply` был выполнен без `--tiers`** и установил лишние процессы,
удалите их службы (данные процессов при этом остаются):

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" remove --tiers <лишние процессы через запятую>
```

### Установка Клиента {#client-install}

На [странице выпусков](#download) к каждому выпуску версии 2.6 прикладываются
два пакета Клиента той же версии:

* **`Telecontrol-SCADA-Client-<версия>-windows-x64.zip`** — для Windows 10 и
  выше. Распакуйте архив в любую папку и запустите `client.exe`. Программа
  не подписана цифровой подписью, поэтому при первом запуске Windows
  SmartScreen может предупредить о ней: нажмите *Подробнее* — *Выполнить в
  любом случае*.
* **`Telecontrol-SCADA-Client-<версия>-macos-arm64.dmg`** — для macOS на
  компьютере с процессором Apple; наименьшая версия macOS указана в описании
  выпуска. Откройте образ диска и
  перетащите программу *Telecontrol SCADA Client* в папку *Программы*.
  Подписана ли программа и заверена ли она Apple, сказано в описании
  выпуска; пакет выпуска 2.6.3 не подписан и не заверен. Если программа не
  заверена, macOS при первом
  открытии откажется ее запускать: после отказа откройте *Системные
  настройки — Конфиденциальность и безопасность* и нажмите *Все равно
  открыть*.

**Эти пакеты пока не содержат модуля отображения мнемосхем** (смотрите
[Отображение мнемосхем](#displays)).

Установщик Сервера `telecontrol-scada-<версия>.msi` задуман так, что
включает и Клиент для Windows: Клиент ставится на каждый компьютер, куда
устанавливается пакет, с пиктограммой *Клиент* на рабочем столе и в меню
*Пуск — ОИК Телеконтроль*. Для версии 2.6 этот установщик пока не опубликован
(смотрите [Загрузка](#download)), поэтому сейчас Клиент устанавливается из
архива или образа диска. Когда установщик будет опубликован:

* **На рабочем месте оператора под Windows** можно вместо архива установить
  этот пакет командой
  `msiexec /i telecontrol-scada-<версия>.msi /qn /norestart /l*v install.log`
  и **не запускайте `scada-setup`**: службы процессов Сервера создает только
  `scada-setup`, поэтому без него процессы Сервера на этом компьютере не
  работают. Лицензия на рабочем месте не нужна.
* **На компьютере Сервера** Клиент тоже устанавливается. Не используйте его
  как рабочее место операторов (смотрите предупреждение о паролях выше).
  Если Клиент на этом компьютере не нужен администратору, удалите пиктограмму
  *Клиент* с рабочего стола.

**ВНИМАНИЕ:** если ООО «Телеконтроль» передало вам отдельный пакет Клиента
или Сервера, не устанавливайте его на компьютер, где уже установлен пакет
`telecontrol-scada-<версия>.msi`, и наоборот, не уточнив порядок в
ООО «Телеконтроль» (mail@telecontrol.ru). У каждого пакета версии 2.6 свой
код обновления установщика Windows, поэтому установка одного не удаляет
другой, но все они устанавливаются в одну папку
`C:\Program Files\Telecontrol SCADA`, и совместная установка не
проверялась.

### Отображение мнемосхем {#displays}

Клиент версии 2.6 отображает мнемосхемы Модус (файлы `.sde` и `.xsde`) и
схемы Видикон (файлы `.vds`) с текущими значениями сам, модулем отображения
мнемосхем, который должен находиться в папке Клиента рядом с его исполняемым
файлом. Компонент ActiveXeme Клиентом версии 2.6 не используется.

**Пакеты Клиента пока не содержат модуля отображения мнемосхем**: условия
его лицензии еще не определены, и модуль поставляется отдельно — обратитесь в
ООО «Телеконтроль». Пока модуля нет, в окне мнемосхемы выводится сообщение
«Модуль отображения мнемосхем не установлен» с причиной; остальные окна
Клиента работают. Для редактирования мнемосхем Модус по-прежнему нужен
Графический редактор Модус.

## Установка под Linux {#linux}

**ВНИМАНИЕ:** пакеты Сервера для Linux версии 2.6 пока не опубликованы
(смотрите [Загрузка](#download)); пока их нет, шаги этого раздела выполнить
нельзя.

Для Linux выпускается пакет Сервера в двух видах —
`telecontrol-scada-server_<версия>_amd64.deb` (Ubuntu, Debian) и архив
`telecontrol-scada-server-<версия>-linux-amd64.tar.gz`. В нем те же процессы,
что и в установщике Windows, кроме `scada-opc` и `scada-vidicon`, и та же
программа `scada-setup`. Пакет устанавливается в папку
`/opt/telecontrol-scada`; нужны Linux x86-64 с systemd и glibc 2.38 и выше
(установка проверялась в контейнере Ubuntu 24.04, на действующем объекте
под Linux — еще нет). Клиента для Linux нет: Клиенты под Windows и macOS
подключаются к Серверу под Linux так же, как к Серверу под Windows.

Все команды выполняйте от имени `root` (через `sudo`; команде `status` это
не нужно, но если лицензию может прочитать только группа `scada`, без `sudo`
она выводит `License: not available`).

1. Установите пакет:

   ```sh
   sudo apt install ./telecontrol-scada-server_<версия>_amd64.deb
   ```

   или распакуйте архив:

   ```sh
   sudo tar -xzf telecontrol-scada-server-<версия>-linux-amd64.tar.gz -C /opt
   ```

2. Поместите файл лицензии в `/var/lib/scada/license.json` с правом чтения
   для всех: процессы читают его от имени учетной записи `scada`. Папки
   `/var/lib/scada` после установки пакета еще нет, поэтому создайте ее:

   ```sh
   sudo mkdir -p /var/lib/scada
   sudo install -m 0644 license.json /var/lib/scada/license.json
   ```

   Лицензию в другом месте укажите параметром `--license`; файл должен быть
   доступен на чтение учетной записи `scada` и не должен лежать в `/home`,
   `/root` или `/run/user` (например, в папке, куда его скачали): службы эти
   папки не видят, и `apply`, `start` и `migrate` откажутся работать с таким путем.
   Каждая папка над файлом тоже должна быть доступна учетной записи `scada`;
   если это не так, `apply` и `start` предупредят. Так же `apply`, `start` и `migrate` не
   принимают в этих папках папку данных (`--data-root`) и папку установки,
   поэтому архив `.tar.gz` распаковывайте в `/opt`, а не в домашнюю папку.

3. Решите, какие процессы будут работать на этом компьютере, и
   [запишите параметры компьютера](#host-parameters).

4. Выполните:

   ```sh
   sudo /opt/telecontrol-scada/bin/scada-setup apply --tiers config,historian,filesystem,iec104,proxy --svc-password <пароль> --root-password <пароль root>
   ```

Параметры `apply` и остальных команд те же, что и под Windows (смотрите
[Установка под Windows](#установка-под-windows) и
[Настройка с помощью scada-setup]({{ '/server/' | relative_url }}#scada-setup)),
отличаются только места:

* папка данных — `/var/lib/scada`: в ней папки процессов
  (`/var/lib/scada/<процесс>/server.json`, у `scada-filesystem` —
  `filestore`) и лицензия;
* каждый процесс работает службой systemd `scada-<процесс>.service`
  (например, `scada-config.service`), которую создает `apply`; службы
  запускаются при загрузке компьютера и перезапускаются при сбое, работают
  от имени системной учетной записи `scada`, которую создает пакет (после
  распаковки архива — `apply`). Пакет и `apply` добавляют учетную запись `scada` в группу
  `dialout`, которой принадлежат последовательные порты, в том числе если
  учетная запись уже существовала. Если `apply` сообщает, что добавил ее в
  `dialout`, перезапустите службы (`stop`, затем `start` с
  [параметрами компьютера](#host-parameters)): уже работающий процесс
  получает доступ к портам только после перезапуска. Если адаптер RS-485
  принадлежит другой группе, добавьте в нее `scada` (`sudo usermod -aG
  <группа> scada`) и перезапустите службы. Процессы протоколов могут
  принимать соединения на портах ниже 1024 (например, на порту 502 для
  ретрансляции по MODBUS TCP);
* пароли `svc` и `root` хранятся в файле
  `/var/lib/scada/secrets/service-secrets.env`, который может прочитать
  только `root` (смотрите
  [Где хранятся пароли]({{ '/server/' | relative_url }}#stored-passwords));
* `scada-setup status` выводит состояние служб так, как его называет
  systemd: `active` — работает, `inactive` — остановлена, `failed` —
  остановилась из-за ошибки. Подробности о службе — `systemctl status
  scada-config`, сообщения процесса — `journalctl -u scada-config` и журнал
  в папке `/var/lib/scada/<процесс>/Logs`;
* `migrate --execute` под Linux недоступна: Сервер версии 2.5 работал только
  под Windows.

**Обновление.** Как и под Windows: остановите процессы, установите новую
версию и выполните `apply` с теми же
[параметрами компьютера](#host-parameters) и паролями — `apply` заново
создает файлы параметров и службы по шаблонам новой версии:

```sh
sudo /opt/telecontrol-scada/bin/scada-setup stop
sudo apt install ./telecontrol-scada-server_<новая версия>_amd64.deb
sudo /opt/telecontrol-scada/bin/scada-setup apply --tiers <процессы этого компьютера> … --svc-password <пароль> --root-password <пароль root>
```

При установке из архива вместо `apt install` распакуйте новый архив поверх
прежнего той же командой `tar -xzf … -C /opt`. Сам `apt install` нового
`.deb`, без `stop`, перезапускает работающие службы с новыми исполняемыми
файлами, но файлы параметров по-прежнему создает только `apply`.

**Удаление.** `sudo apt remove telecontrol-scada-server` останавливает и
удаляет службы процессов и сертификат компьютера; данные в `/var/lib/scada`
и удостоверяющий центр объекта (на центральном компьютере — папка
`/opt/telecontrol-scada/data/Certificates/ca`) остаются, и после повторной
установки остальные компьютеры подключать заново не нужно. Сертификат самого
центрального компьютера удаляется, и следующий `apply` создает новый с другим
отпечатком, но остальные компьютеры узнают его по удостоверяющему центру, и
менять на них ничего не нужно. Новый отпечаток понадобится только для
подключения новых компьютеров — его выводит `scada-setup status` на
центральном компьютере (смотрите
[Отпечаток центрального компьютера изменился]({{ '/server/' | relative_url }}#central-fingerprint-changed)).
`sudo apt purge telecontrol-scada-server` удаляет и всю папку
`data/Certificates` вместе с удостоверяющим центром — так удаляйте
программу, только если компьютер навсегда выводится из объекта. При
установке из архива сначала выполните `sudo /opt/telecontrol-scada/bin/scada-setup
remove`, затем удалите папку `/opt/telecontrol-scada`; на центральном
компьютере, если программа будет установлена снова, сначала сохраните
подпапку `data/Certificates/ca` и верните ее до `apply` (смотрите
[Новый удостоверяющий центр]({{ '/server/' | relative_url }}#opcua-renewal)).
Учетная запись `scada` при удалении остается, в том числе после `apt purge`;
если она больше не нужна, удалите ее командой `sudo userdel scada`.

**Ни `apt remove`, ни `apt purge` не удаляют папку данных `/var/lib/scada`**
— в ней остаются конфигурация, архивы и лицензия. `apt purge` удаляет из нее
только папку `secrets` с файлом `service-secrets.env`, где пароли `svc` и
`root` хранятся в незашифрованном виде; после `apt remove` остается и он.
Если данные больше не нужны, удалите папку командой
`sudo rm -rf /var/lib/scada`, а также удалите правила брандмауэра, созданные
в разделе [Настройка сети](#network).

## Лицензия {#license}

Лицензия — подписанный файл `license.json`, в котором перечислены приобретенные
процессы и срок действия. Один и тот же файл кладется на все компьютеры объекта.
Процесс, не названный в лицензии, останавливается сразу после запуска.
Лицензию, срок действия которой еще не начался, не принимают ни процессы, ни
`scada-setup`. Демонстрационного режима без лицензии в версии 2.6 нет: для
оценки системы запросите лицензию в ООО «Телеконтроль» (mail@telecontrol.ru)
(смотрите [Лицензирование]({{ '/server/' | relative_url }}#licensing)).

**Срок действия.** Срок окончания лицензии показывает команда
`scada-setup status` (строка `License: … (<идентификатор лицензии>, expires …)`;
у истекшей — `EXPIRED` и дата). Идентификатор лицензии называет, кому она
выдана; сообщайте его, обращаясь в ООО «Телеконтроль» по поводу лицензии. Проверяйте его сами: предупреждения об окончании
срока Сервер выдает только системными событиями в Клиенте, за 30 дней до
окончания. После окончания срока процессы продолжают работать, но отклоняют
запросы Клиентов, пока лицензия не будет заменена.

С истекшей лицензией `scada-setup` предупреждает об этом, но по-прежнему
исходит из процессов, указанных в лицензии: `apply` без `--tiers` установит
ровно их.

**Замена файла лицензии.** Работающие процессы перечитывают файл каждые
5 секунд и подхватывают новую лицензию без перезапуска. Поэтому заменяйте
файл за один шаг: скопируйте новую лицензию в ту же папку под временным
именем, а затем переименуйте ее в `license.json`, заменив старый файл:

```bat
copy new-license.json "%ProgramData%\Telecontrol\SCADA Server\license.new"
move /y "%ProgramData%\Telecontrol\SCADA Server\license.new" "%ProgramData%\Telecontrol\SCADA Server\license.json"
```

Под Linux новый файл должен быть доступен на чтение учетной записи `scada`:

```sh
sudo install -m 0644 new-license.json /var/lib/scada/license.new
sudo mv -f /var/lib/scada/license.new /var/lib/scada/license.json
```

**ВНИМАНИЕ:** если в момент проверки файла нет, он записан не полностью
(например, при копировании поверх старого файла) или под Linux недоступен на
чтение учетной записи `scada`, процесс считает, что лицензии нет, и
останавливается. Ни Windows, ни systemd под Linux такую службу автоматически
не перезапускают: после замены файла запустите процессы командой `start` с
[параметрами компьютера](#host-parameters):

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" start --tiers <процессы этого компьютера> [--license <путь>]
```

```sh
sudo /opt/telecontrol-scada/bin/scada-setup start --tiers <процессы этого компьютера> [--license <путь>]
```

Если на этом компьютере нет `scada-proxy` (только процессы протокольного уровня), больше ничего перезапускать не нужно: объекты его процессов сами снова обновляются и архивируются — смотрите [Перезапуск процесса протокольного уровня]({{ '/server/' | relative_url }}#edge-restart).

**Добавление процесса.** Замените файл новой лицензией на всех компьютерах.
На компьютере, где будет работать новый процесс, выполните
`scada-setup apply` с полным списком процессов этого компьютера в `--tiers`,
включая новый, и с теми же остальными параметрами, что и при установке
(смотрите [Повторный apply]({{ '/server/' | relative_url }}#reapply)).
Запишите новый список. Если на этом компьютере нет `scada-proxy` (только процессы протокольного уровня), больше ничего перезапускать не нужно: объекты его процессов сами снова обновляются и архивируются — смотрите [Перезапуск процесса протокольного уровня]({{ '/server/' | relative_url }}#edge-restart).

Лицензия, выданная для виртуальной машины Google Cloud, проверяется только на
этой машине; любая другая лицензия не привязана к компьютеру, и для нее ничего
настраивать не нужно. Подробности — в разделе [Лицензирование]({{ '/server/' | relative_url }}#licensing).

## Пароль root

Встроенная учетная запись `root` имеет все права. Ее пароль задается
параметром `--root-password` команды `scada-setup apply` (или переменной
окружения `SCADA_SETUP_ROOT_PASSWORD`). На компьютере, где работает
`scada-config` или `scada-filesystem`, `apply` без этого пароля не
выполняется: эти процессы хранят конфигурацию в собственных БД, у каждого
своя учетная запись `root`, и без заданного пароля она принимала бы вход с
пустым паролем.

`scada-setup` сохраняет пароль в
[файле паролей]({{ '/server/' | relative_url }}#stored-passwords) компьютера, а
не в файлах параметров, и процессы заново записывают его при каждом запуске.
Поэтому:

* **чтобы сменить пароль `root`, выполните в командной строке с правами
  администратора**

  ```bat
  "C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" set-password --root-password <новый пароль>
  ```

  на каждом компьютере, где работает один из этих процессов. Команда
  сохраняет новый пароль и перезапускает службы процессов этого компьютера;
* **из Клиента пароль `root` не меняется**: Сервер отказывает в такой смене, и
  Клиент сообщает об этом в журнале событий, а не принимает пароль, который
  при следующем запуске процесса был бы заменен;
* при каждом повторном `apply`, в том числе при обновлении, указывайте
  действующий пароль `root`.

Подробности — в разделе
[Пароль root]({{ '/server/' | relative_url }}#root-password).

## Настройка сети {#network}

`scada-setup` правила брандмауэра не создает — откройте входящие порты
вручную:

* **для рабочих мест Клиентов** — порт TCP 2000 на центральном компьютере
  (с `scada-proxy`);
* **если процессы установлены на нескольких компьютерах:**
  * на центральном компьютере — порты 4840 (`scada-proxy`), 4841
    (`scada-config`) и 4842 (`scada-historian`) для компьютеров с
    процессами протокольного уровня: при запуске они читают из архива
    последние значения своих объектов;
  * на каждом компьютере с процессами протокольного уровня — порт OPC UA
    каждого из его процессов (по таблице ниже) для центрального компьютера:
    к ним подключается `scada-proxy`.

Если все процессы работают на одном компьютере, открывать нужно только
порт 2000.

Правила можно создать в командной строке с правами администратора (адреса в
примере замените адресами своих компьютеров; в `remoteip` их перечисляют
через запятую):

```bat
rem Центральный компьютер: Клиенты (можно ограничить адресами рабочих мест через remoteip=...)
netsh advfirewall firewall add rule name="Telecontrol SCADA Clients" dir=in action=allow protocol=TCP localport=2000
rem Центральный компьютер, если есть другие компьютеры Сервера (здесь 10.0.0.11 и 10.0.0.12):
netsh advfirewall firewall add rule name="Telecontrol SCADA OPC UA" dir=in action=allow protocol=TCP localport=4840,4841,4842 remoteip=10.0.0.11,10.0.0.12
rem Компьютер с scada-modbus и scada-iec104 (центральный компьютер — 10.0.0.10):
netsh advfirewall firewall add rule name="Telecontrol SCADA OPC UA" dir=in action=allow protocol=TCP localport=4843,4844 remoteip=10.0.0.10
```

**Под Linux** откройте те же порты средствами своего дистрибутива, например
на Ubuntu:

```sh
# Центральный компьютер: Клиенты
sudo ufw allow proto tcp to any port 2000
# Центральный компьютер, если есть другие компьютеры Сервера:
sudo ufw allow proto tcp from 10.0.0.11 to any port 4840,4841,4842
sudo ufw allow proto tcp from 10.0.0.12 to any port 4840,4841,4842
# Компьютер с scada-modbus и scada-iec104:
sudo ufw allow proto tcp from 10.0.0.10 to any port 4843,4844
```

В дистрибутивах с firewalld то же делают правила вида
`sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.0.11 port port=4840-4842 protocol=tcp accept'`
(для порта Клиентов — `sudo firewall-cmd --permanent --add-port=2000/tcp`), а
затем `sudo firewall-cmd --reload`.

**Направления, принимающие подключения.** Если направление работает
пассивно — его «Транспорт» имеет тип «TCP Server», и ОИК сам ждет
подключения (например, [ретрансляция в диспетчерский центр]({{ '/dev/devices/' | relative_url }}#retransmission)
по МЭК 60870-5-104, обычно порт 2404), — откройте его порт на компьютере
процесса протокольного уровня, только для адресов, которые должны
подключаться.

| Процесс | OPC UA | Клиенты |
|---|:-:|:-:|
| `scada-proxy` | 4840 | 2000 |
| `scada-config` | 4841 | 2001 |
| `scada-historian` | 4842 | 2002 |
| `scada-modbus` | 4843 | 2003 |
| `scada-iec104` | 4844 | 2004 |
| `scada-iec61850` | 4845 | 2005 |
| `scada-filesystem` | 4846 | 2006 |
| `scada-opc` | 4847 | 2007 |
| `scada-vidicon` | 4848 | 2008 |

**Порты OPC UA 4840–4848 должны быть доступны только с компьютеров
объекта.** Процессы подключаются друг к другу с шифрованием и принимают
только компьютеры, сертификат которых выдал удостоверяющий центр объекта
(смотрите [Удостоверяющий центр объекта]({{ '/server/' | relative_url }}#opcua-site-ca)).
`scada-config` принимает соединение с сертификатом любого компьютера, чтобы
к объекту можно было подключить новый компьютер. Сертификат объекта он
выдает только учетной записи `svc`: ни `root`, ни пользователь с правом
«Настройка конфигурации» получить его не может, и Клиент такого права не
дает. Поэтому для подключения компьютера к объекту нужен пароль `svc`;
храните его так же, как пароль `root`. Регистрацию процесса `scada-config` и
`scada-proxy` принимают только по сертификату, который выдал удостоверяющий
центр объекта, и только под именем, указанным в этом сертификате; сертификат,
перенесенный в папку `trusted`, позволяет подключиться, но не
зарегистрироваться.
Если к Серверу должна подключаться внешняя система OPC UA, разрешите доступ
к порту 4840 только с ее адреса: этот порт принимает только защищенные
соединения с входом по имени пользователя, а незащищенные соединения и
анонимный вход — только с параметром `--allow-anonymous-opcua` (смотрите
[Подключение внешней системы]({{ '/server/' | relative_url }}#opcua-external)).
**На объекте, настроенном с `--insecure-links`,** эти порты защищает только
брандмауэр: компьютер, получивший к ним доступ, может подключиться к
процессам Сервера или выдать себя за один из них.

Порты 2001–2008 остальных процессов тоже принимают вход пользователей, но
Клиентам не нужны: не открывайте их.

## Подготовка проекта {#project}

**Новая установка начинается с пустого проекта.** Конфигурационные БД,
которые создает `apply`, не содержат ни объектов, ни устройств, ни связей,
ни пользователей: в них только служебная учетная запись `svc`, через
которую процессы подключаются друг к другу. Войти в Клиент можно встроенной
учетной записью `root` с паролем из `--root-password`. Процессы
протокольного уровня ни к чему не подключаются и не занимают порты
устройств, пока вы не создадите связи. Создайте конфигурацию проекта в
Клиенте (смотрите [Проектирование]({{ '/development/' | relative_url }}))
или поставьте на место готовую БД проекта (ниже).

Конфигурация хранится в одной копии — в папке `config/Configuration`
процесса `scada-config`. Остальные процессы читают ее у `scada-config`:
процессы протокольного уровня — свои устройства и объекты, `scada-historian`
— список архивов и их назначение объектам, `scada-proxy` — имена, пароли и
роли пользователей Клиента. Поэтому изменение конфигурации, внесенное в
Клиенте, — создание, переименование и удаление объектов, устройств и
пользователей, назначение ролей — сразу действует во всех процессах. У
`scada-filesystem` есть своя БД в папке `filestore/Configuration`, но в ней
только служебная учетная запись `svc`: `apply` удаляет из нее все остальное,
и заменять ее не нужно.

### Демонстрационный проект {#demo}

Чтобы ознакомиться с системой без оборудования, установите
демонстрационный проект: добавьте `--demo` к первой команде `apply` на
центральном компьютере. Тогда конфигурационные БД создаются из
демонстрационной конфигурации из состава установщика: в ней 41 аналоговый и
52 дискретных объекта, сигналы эмуляции, две включенные связи
МЭК 60870-5-104 (одна из них принимает подключения на порту 2404 этого
компьютера — его занимает процесс `scada-iec104`, если он установлен), два
архива и пользователи «Клиент 1» … «Клиент 10» и `guest`, которым **не
заданы пароли**. Демонстрационные мнемосхемы копируются в файловое хранилище
`scada-filesystem`.

**Не устанавливайте демонстрационный проект на Сервер, доступный из сети
объекта**: под его пользователями может войти кто угодно, без пароля. В
списке пользователей демонстрационного проекта есть и пользователь `root` —
это не встроенная учетная запись `root`: вход под именем `root` всегда
выполняется встроенной учетной записью с паролем из `--root-password`, а
этот пользователь войти не может никогда. Не изменяйте и не удаляйте его,
считая настоящим `root`.

`--demo` действует только на конфигурационные БД, которых еще нет: на уже
установленном компьютере `apply --demo` ничего не заменяет и сообщает
`Kept the existing configuration DB of …`. Чтобы перейти от
демонстрационного проекта к пустому, остановите процессы, удалите файл
`configuration.sqlite3` из папки `config/Configuration` в папке данных и
выполните `apply` без `--demo` с прежними
[параметрами компьютера](#host-parameters) и паролями. Демонстрационные
мнемосхемы удалите из папки `filestore/FileSystem`. Можно и удалить
демонстрационные устройства, объекты и пользователей в Клиенте: изменение
доходит до всех процессов. В обоих случаях проверьте затем, что порт 2404
больше никто не занимает (команда `netstat -ano | findstr :2404` на
компьютере `scada-iec104` ничего не выводит) и что под пользователем
«Клиент 1» войти больше нельзя.

### Готовая БД проекта {#project-db}

Чтобы поставить на место готовую конфигурационную БД проекта
(`configuration.sqlite3` версии 2.6), на центральном компьютере:

1. Остановите процессы:
   `"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" stop`.
2. Скопируйте файл в папку `config\Configuration` внутри
   `%ProgramData%\Telecontrol\SCADA Server`, заменив созданную `apply`
   базу. Другие процессы своей базы конфигурации не хранят. Папка
   `proxy\Configuration`, оставшаяся от более ранней сборки 2.6, больше не
   используется.
3. Выполните `scada-setup apply` с теми же
   [параметрами компьютера](#host-parameters) и паролями, что и при
   установке. Он сохраняет скопированную базу и добавляет в нее служебную
   учетную запись `svc` (идентификатор 100), без которой процессы не смогут
   подключиться друг к другу. **Пользователь проекта с идентификатором 100
   будет заменен учетной записью `svc`.** Если база взята с другого объекта
   версии 2.6, в ней сохранен пароль `svc` того объекта: на этом объекте нужен
   тот же пароль `svc`, иначе процессы не подключатся друг к другу.

Под Linux команды те же — `sudo /opt/telecontrol-scada/bin/scada-setup stop`
и `apply`, — а папка `config/Configuration` находится
в `/var/lib/scada` (смотрите [Установка под Linux](#linux)).

Конфигурацию Сервера версии 2.5 переносите командой `scada-setup migrate`:
она переносит и пароли пользователей, которые версия 2.5 хранила в отдельном
файле (смотрите [Обновление с версии 2.5](#upgrade-2-5)).

На каждом рабочем месте скопируйте файлы мнемосхем (`.sde`) в папку
*%ProgramData%\Telecontrol\SCADA Client*. При использовании
[серверной файловой системы]({{ '/server/' | relative_url }}#filesystem)
достаточно загрузить файлы мнемосхем на сервер.

Чтобы ознакомиться с системой без оборудования, установите
[демонстрационный проект](#demo) или задайте объектам своего проекта
[эмуляцию]({{ '/architecture/' | relative_url }}#эмуляция).

Подробности о создании проекта и настройке оборудования смотрите в разделе [Проектирование]({{ '/development/' | relative_url }}).

## Запуск Сервера

Службы процессов запускаются автоматически вместе с Windows; вход
пользователя в систему не требуется. При сбое процесса Windows перезапускает
его службу (смотрите [Службы Windows]({{ '/server/' | relative_url }}#services)).
Запустить или остановить все процессы компьютера в правильном порядке можно
командами `start` и `stop`; `start` — только с
[параметрами компьютера](#host-parameters):

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" stop
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" start --tiers <процессы этого компьютера> [--license <путь>]
```

Для диагностики процесс может быть запущен в
[консольном режиме]({{ '/server/' | relative_url }}#console).

## Запуск Клиента {#client-start}

Запустите `client.exe` из папки, куда распакован архив Клиента, или на macOS —
программу *Telecontrol SCADA Client* из папки *Программы*. Пиктограмму
*Клиент* на рабочем столе и в меню *Пуск — ОИК Телеконтроль* создает только
установщик Сервера, который для версии 2.6 пока не опубликован. При этом будут запрошены реквизиты пользователя ОИК для подключения к Серверу:

![]({{ '/img/client-login.png' | relative_url }})

При первом запуске войдите как *root* с паролем, заданным параметром
`--root-password` при установке.

Строка *Сервер* состоит из двух полей. Слева — список типов сервера (он
показывается, только если Клиент поддерживает больше одного типа): выберите
**«Телеконтроль»**.

> **Внимание.** Тип «OPC UA» подключает Клиент по протоколу OPC UA. После
> потери связи Клиент переподключается сам, как и при типе «Телеконтроль»
> (смотрите [Связь с Сервером]({{ '/client/' | relative_url }}#connection)).
> Для работы с Сервером ОИК используйте тип «Телеконтроль».

Справа введите имя или адрес IP компьютера, где работает процесс
`scada-proxy`, если он отличается от текущего. Иначе поле оставьте
пустым.

Раскрывающийся раздел «Защита и сертификаты» (режим защиты, сертификат и
закрытый ключ клиента) появляется только для типа «OPC UA»; для типа
«Телеконтроль» заполнять его не нужно.

В режимах «Максимальная безопасность» и «Подпись и шифрование» Клиент проверяет
подлинность Сервера по его сертификату:
{: #server-certificate-check}

* Сертификат и закрытый ключ самого Клиента указывать не обязательно: если
  поля пусты, Клиент при первом подключении создает свой сертификат сам.
* Встретив сертификат Сервера впервые, Клиент спрашивает: «Сервер предъявил
  сертификат, которому этот компьютер ещё не доверял», — и показывает его
  владельца и отпечаток SHA-256. Сравните отпечаток с опубликованным
  администратором Сервера и ответьте *Да*, чтобы доверять сертификату и
  подключиться.
* Если сервер по тому же адресу предъявил *другой* сертификат, Клиент
  предупреждает: «ВНИМАНИЕ: сервер по этому адресу предъявил ДРУГОЙ
  сертификат…». Так выглядел бы перехват соединения: доверяйте новому
  сертификату, только если администратор Сервера подтвердил его замену.

Сертификаты хранятся в папке `pki` данных пользователя Клиента:
`%APPDATA%\Telecontrol\SCADA Client\pki` в Windows и
`~/Library/Application Support/Telecontrol/SCADA Client/pki` в macOS. Чтобы
перестать доверять Серверу, удалите его сертификат из вложенной папки
`trusted`.

При установленном флаге *Входить автоматически в следующий раз* Клиент
запоминает имя и пароль на этом компьютере и при каждом запуске не ждёт ввода
в окне входа: он сразу входит под последней учётной записью. Окно входа,
открытое командами *Отключиться от сервера* и *Подключиться к серверу...*,
ждёт ввода всегда.

> **Внимание.** Не устанавливайте этот флаг на общем диспетчерском рабочем
> месте: при запуске Клиент войдёт под учётной записью сдающего смену. Чтобы
> войти под своей и снять флаг, удерживайте при запуске Клиента *Ctrl* (на
> macOS — *Option*) — окно входа откроется со снятым флагом — и войдите. Можно
> также нажать *Отмена*, пока идёт автоматический вход (смотрите
> [Автоматический вход]({{ '/client/' | relative_url }}#auto-login)).

## Первые шаги после входа

**В новой установке проект пуст:** панели объектов и оборудования ничего не
показывают, пока вы не создадите конфигурацию или не поставите на место
готовую БД проекта (смотрите [Подготовка проекта](#project)). Если Сервер
установлен с `--demo`, вы видите [демонстрационный проект](#demo).

После входа в систему:

1. **Откройте панель объектов** — меню *Дополнительно — Объекты*. В панели отображается дерево объектов с текущими значениями. Двойной клик по объекту открывает его график.

2. **Просмотрите мнемосхемы** — меню *Мнемосхема*. Выберите доступную схему из списка.

3. **Проверьте состояние оборудования** — меню *Дополнительно — Оборудование*. Иконки слева от устройств показывают состояние связи.

4. **Создайте пользователей** — меню *Дополнительно — Пользователи*. Создайте учетные записи для операторов и работайте под ними, а не под *root*. Смотрите [Конфигурирование пользователей]({{ '/dev/users/' | relative_url }}). Создав пользователя и задав ему пароль, проверьте, что под ним можно войти.

   Права учетной записи определяются только ее **ролями**: новая учетная
   запись может лишь просматривать данные, пока ей не назначены роли.
   Назначьте их командой *Роли…* из контекстного меню пользователя: `Operator`
   — управление, `ConfigureAdmin` — настройка конфигурации (смотрите
   [Права доступа]({{ '/dev/users/' | relative_url }}#access-rights)).

   В списке пользователей есть служебная учетная запись `svc`: через нее
   процессы Сервера подключаются друг к другу, и Сервер не дает изменить ее
   из Клиента. Ее пароль меняет только `scada-setup set-password` (смотрите
   [Учетная запись svc]({{ '/server/' | relative_url }}#svc)).

Далее смотрите описание [Клиента]({{ '/client/' | relative_url }}).

## Обновление

Этот порядок — для обновления версии 2.6 и новее. Сервер версии 2.5 и ранее
был одним процессом с одной службой, и его данные нужно перенести в процессы
версии 2.6 — смотрите [ниже](#upgrade-2-5).

**Перед каждым обновлением сделайте резервную копию каждого компьютера
Сервера** — смотрите
[Резервное копирование]({{ '/server/' | relative_url }}#backup). Эта копия —
единственный путь назад: установщик отказывается ставить более старую версию
поверх новой, поэтому неудачное обновление отменяют переустановкой прежней
версии и восстановлением резервной копии (смотрите
[Возврат после неудачного обновления]({{ '/server/' | relative_url }}#rollback-upgrade)).

**На компьютерах Сервера** — сначала на центральном, затем на каждом
компьютере с процессами протокольного уровня — в командной строке с правами
администратора:

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" stop
msiexec /i telecontrol-scada-<новая версия>.msi /qn /norestart /l*v install.log
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" apply --tiers <процессы этого компьютера> [--central <адрес>] [--advertise <адрес>] [--license <путь>] --svc-password <пароль> --root-password <пароль root>
```

Повторите в `apply` все [параметры компьютера](#host-parameters), что и
при установке, — в том числе `--central-fingerprint`, `--assigned-links-only`,
`--host-name`, `--insecure-links`, `--allow-anonymous-opcua` и `--data-root`,
если они задавались, — и действующий
пароль `svc`. Установщик заменяет только исполняемые
файлы; `apply` заново создает файлы параметров (свои параметры храните в
[`server.override.json`]({{ '/server/' | relative_url }}#server-override) — он
сохраняется) и не трогает данные. На компьютерах только с процессами
протокольного уровня `--root-password` можно не указывать.

На объекте из нескольких компьютеров, пока обновляются компьютеры с
процессами протокольного уровня, объекты их процессов помечаются как
недостоверные; после обновления они снова обновляются и архивируются сами
(смотрите
[Перезапуск процесса протокольного уровня]({{ '/server/' | relative_url }}#edge-restart)).

**На рабочих местах операторов** установите Клиент новой версии так же, как
прежний (смотрите [Установка Клиента](#client-install)): распакуйте новый
архив или образ диска вместо прежнего или установите новый пакет, без команд
`scada-setup`. Модуль отображения мнемосхем в пакеты Клиента не входит:
перенесите его из прежней папки Клиента в новую (`display_runtime.dll` рядом
с `client.exe`; на macOS `libdisplay_runtime.dylib` в папке
*Contents/Frameworks* программы), иначе в окнах мнемосхем будет сообщение
«Модуль отображения мнемосхем не установлен».


```bat
msiexec /i telecontrol-scada-<новая версия>.msi /qn /norestart /l*v install.log
```

### Обновление с версии 2.5 {#upgrade-2-5}

Сервер версии 2.5 работал одной службой *Telecontrol SCADA Server* и
использовал аппаратный ключ. Установщик версии 2.6 заменяет программу версии
2.5, поэтому **проверьте план перехода до установки 2.6**: то, что мешает
переходу, исправляется только в версии 2.5.

Как вернуться к версии 2.5, описано в разделе
[Возврат к версии 2.5]({{ '/server/' | relative_url }}#rollback-2-5).

На компьютере, где работал Сервер 2.5:

1. Получите лицензию версии 2.6 и положите ее в
   `%ProgramData%\Telecontrol\SCADA Server\license.json`.
2. Сделайте резервную копию папки `%ProgramData%\Telecontrol\SCADA Server`.
3. Распакуйте пакет 2.6 во временную папку, не устанавливая его, и выполните
   распакованной программой `scada-setup migrate` — она ничего не меняет и
   выводит план. Исправьте в версии 2.5 то, что мешает переходу, и повторите
   проверку. Порядок описан в разделе
   [Переход с версии 2.5]({{ '/server/' | relative_url }}#upgrade-2-5).
4. Установите пакет версии 2.6
   (`msiexec /i telecontrol-scada-<версия>.msi /qn /norestart /l*v install.log`).
5. В командной строке с правами администратора выполните:

   ```bat
   "C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" migrate --execute --tiers config,historian,filesystem,iec104,proxy --svc-password <пароль> --root-password <пароль root>
   ```

   В `--tiers` перечислите процессы этого компьютера: `config`,
   `historian`, `filesystem`, `proxy` и **процесс протокольного уровня для
   каждого протокола**, по которому работают устройства версии 2.5 (в
   примере — `iec104`; для MODBUS — `modbus`, для МЭК 61850 — `iec61850`).
   Если такой процесс пропущен, план перехода предупреждает об этом строкой
   `WARNING: … will not run the '<процесс>' process`: данные с устройств
   этого протокола тогда не собираются, если процесс не работает на другом
   компьютере.

   Команда удаляет старую службу, копирует конфигурацию, пользователей с
   паролями, архивы и файлы мнемосхем в папки процессов 2.6 и запускает их,
   как `apply` (в том числе создает сертификат Сервера). Пароль `root` версии
   2.5 при этом заменяется паролем из `--root-password` (смотрите
   [Пароль root](#пароль-root)). **Если команда завершилась ошибкой после
   копирования, не повторяйте `migrate`** — завершите переход командой
   `apply` с теми же `--tiers` и паролями (смотрите
   [Переход с версии 2.5]({{ '/server/' | relative_url }}#upgrade-2-5)).
6. Установите Клиент версии 2.6 на **каждом** рабочем месте (смотрите
   [Установка Клиента](#client-install)): работа Клиента версии 2.5 с
   Сервером 2.6 не проверялась.
7. Проверьте работу Клиентом.

Старые папки `Configuration`, `History` и `FileSystem` не изменяются и не
удаляются.

## Удаление {#uninstall}

Удалите программу *ОИК Телеконтроль* (издатель — ООО Телеконтроль) в
*Панели управления — Программы и компоненты*. Установщик сам останавливает и
удаляет службы процессов вместе с их параметрами в реестре, а также
сертификат Сервера этого компьютера и его закрытый ключ. Папку данных
`%ProgramData%\Telecontrol\SCADA Server` (в ней и файл паролей `svc` и
`root`) и правила брандмауэра, созданные в
разделе [Настройка сети](#network), он оставляет — их удаляют вручную.

**Удостоверяющий центр объекта на центральном компьютере установщик
оставляет**, поэтому после повторной установки остальные компьютеры
подключать заново не нужно. Сертификат самого центрального компьютера
установщик удаляет, и следующий `apply` создает новый с другим отпечатком,
но остальные компьютеры узнают его по удостоверяющему центру, и менять на
них ничего не нужно. Новый отпечаток понадобится только для подключения
новых компьютеров — его выводит `scada-setup status` на центральном
компьютере (смотрите
[Отпечаток центрального компьютера изменился]({{ '/server/' | relative_url }}#central-fingerprint-changed)).
Если компьютер навсегда выводится из объекта,
удалите программу командой
`msiexec /x telecontrol-scada-<версия>.msi SCADA_PURGE_CERTIFICATES=1` —
тогда удаляется вся папка
`C:\Program Files\Telecontrol SCADA\data\Certificates`, вместе с
удостоверяющим центром. Порядок описан в разделе
[Удаление Сервера]({{ '/server/' | relative_url }}#uninstall). Клиент,
распакованный из архива или образа диска, удаляется вместе с его папкой
(на macOS — программой в папке *Программы*). Свои настройки и данные Клиент
хранит отдельно, и при этом они остаются:

* под Windows — настройки входа в разделе реестра
  `HKEY_CURRENT_USER\Software\Telecontrol\Workplace`, профиль, папку
  сертификатов `pki` и прочие данные пользователя в
  `%APPDATA%\Telecontrol\SCADA Client`, общие данные в
  `%ProgramData%\Telecontrol\SCADA Client` и журналы в
  `%LOCALAPPDATA%\Telecontrol\SCADA Client\logs`;
* на macOS — настройки входа в файле
  `~/Library/Application Support/Telecontrol/SCADA Client/settings.json`,
  данные в той же папке и журналы в `~/Library/Logs/Telecontrol/SCADA Client`.

Если был включен автоматический вход, пароль пользователя хранится под
Windows в зашифрованном виде в том же разделе реестра, а на macOS — в связке
ключей пользователя, в записи «Telecontrol SCADA Client»; удаление папок ее
не затрагивает. Выводя рабочее место из эксплуатации, удалите этот раздел
реестра и папки, а на macOS — и эту запись в программе «Связка ключей», у
каждого пользователя компьютера.

## Устранение неполадок

Команды `scada-setup`, упомянутые ниже, кроме `status`, выполняйте из
командной строки с правами администратора.

<dl>

<dt>Клиент не может подключиться к Серверу</dt>
<dd>Убедитесь, что служба <em>Telecontrol SCADA Proxy</em> запущена
(<code>scada-setup status</code> на ее компьютере). Проверьте, что порт 2000
разрешен в брандмауэре и доступен по сети.</dd>

<dt>Процесс Сервера останавливается сразу после запуска</dt>
<dd>Нет действительного файла лицензии или лицензия не включает этот процесс,
либо удален один из файлов <a href="{{ '/server/' | relative_url }}#opcua-certificate">сертификата Сервера</a>
(в журнале — <code>Can't open file</code>; <code>scada-setup apply</code> в этом
случае сообщает, какого файла не хватает). Причина записывается в
<a href="{{ '/server/' | relative_url }}#logging">журнал процесса</a>. Смотрите
<a href="{{ '/server/' | relative_url }}#licensing">Лицензирование</a>.</dd>

<dt>Служба останавливается или постоянно перезапускается после изменения параметров</dt>
<dd>Скорее всего, ошибка в файле параметров <code>server.json</code>
(например, после правки вручную): в
<a href="{{ '/server/' | relative_url }}#logging">журнале процесса</a> — в папке
<code>Logs</code> рядом с файлом параметров — есть строка
<code>Can't load parameters file</code> или <code>Invalid log configuration</code>
с описанием ошибки. Свои параметры записывайте не в <code>server.json</code>, а в
<a href="{{ '/server/' | relative_url }}#server-override"><code>server.override.json</code></a>,
и выполните <code>scada-setup apply</code>.</dd>

<dt>Процессы протокольного уровня не получают конфигурацию</dt>
<dd>Если в журнале процесса протокольного уровня есть
<code>Bad_UserAccessDenied</code>, пароль <code>svc</code> на этом компьютере
не совпадает с паролем центрального компьютера. Выполните на нем
<code>scada-setup set-password --svc-password &lt;действующий пароль svc
центрального компьютера&gt;</code> (смотрите
<a href="{{ '/server/' | relative_url }}#svc-rotate">Смена пароля svc</a>). Если на этом компьютере нет <code>scada-proxy</code>, больше ничего перезапускать не нужно: объекты его процессов сами снова обновляются и архивируются (смотрите <a href="{{ '/server/' | relative_url }}#edge-restart">Перезапуск процесса протокольного уровня</a>).</dd>

<dt>Устройства компьютера с процессами протокольного уровня так и не появляются</dt>
<dd>Клиент не показывает устройства, которые обслуживает компьютер с
процессами протокольного уровня, хотя <code>scada-setup status</code> на нем
показывает, что процессы работают. <code>scada-proxy</code> подключается к
этому компьютеру по имени, которое тот сообщил; если центральный компьютер
не разрешает это имя (проверьте командой <code>ping &lt;имя компьютера&gt;</code>
на центральном компьютере), выполните на компьютере с процессами
протокольного уровня <code>scada-setup apply</code>
с его <a href="#host-parameters">параметрами компьютера</a> и
<code>--advertise &lt;его адрес IP&gt;</code> и запишите этот параметр.
Чтобы новый адрес попал и в
<a href="{{ '/server/' | relative_url }}#opcua-certificate">сертификат Сервера</a>,
перед этим <code>apply</code> удалите оба файла сертификата. Проверьте также,
что брандмауэр этого компьютера пропускает центральный компьютер к портам
OPC UA его процессов (смотрите <a href="#network">Настройка сети</a>).
Исправив адрес, перезапускать службу <em>Telecontrol SCADA Historian</em> не
нужно: архив начнет получать значения этих объектов сам. Если окна Клиента с
объектами этого компьютера были открыты до исправления, на всякий случай
попросите диспетчеров перезапустить Клиент.</dd>

<dt>Все процессы остановились после замены файла лицензии</dt>
<dd>Файл был недоступен или записан не полностью в момент проверки. Положите
действительный файл (смотрите <a href="#license">Замена файла лицензии</a>) и
выполните <code>scada-setup start</code> с
<a href="#host-parameters">параметрами компьютера</a>. Если на этом компьютере нет <code>scada-proxy</code>, больше ничего перезапускать не нужно: объекты его процессов сами снова обновляются и архивируются (смотрите <a href="{{ '/server/' | relative_url }}#edge-restart">Перезапуск процесса протокольного уровня</a>).</dd>

<dt><code>scada-setup start</code> прерывается с ошибкой</dt>
<dd>Процессы, служб которых на компьютере нет, <code>start</code> пропускает
(<code>Skipped &lt;процесс&gt;: not installed on this host</code>), а с ошибкой
<code>none of the requested tier services is installed on this host</code>
завершается, только если на компьютере нет ни одной из запрошенных служб:
значит, в <code>--tiers</code> перечислены не те процессы или
<code>apply</code> на этом компьютере еще не выполнялся. Повторите ее с
<a href="#host-parameters">параметрами компьютера</a>.</dd>

<dt>Процесс работает, но отклоняет запросы</dt>
<dd>Лицензия не проверена или истекла (срок — в выводе
<code>scada-setup status</code>). Если файл параметров процесса составлен
вручную, проверьте путь в <code>"license": {"file": ...}</code>
(<code>scada-setup</code> задает его сам). Лицензия, выданная для виртуальной
машины Google Cloud, на другом компьютере не проверяется. При истекшей
лицензии замените файл — перезапуск не нужен.</dd>

<dt>Значения перестали записываться в архив</dt>
<dd>Пока служба процесса протокольного уровня (например,
<em>Telecontrol SCADA IEC 104</em>) остановлена или перезапускается, в том
числе автоматически после сбоя, значения его объектов в архив не
записываются. После запуска процесса запись возобновляется сама, обычно в
течение минуты; перезапускать <em>Telecontrol SCADA Historian</em> или Клиент
не нужно (смотрите <a href="{{ '/server/' | relative_url }}#edge-restart">Перезапуск
процесса протокольного уровня</a>). Если запись не возобновилась, проверьте
<code>scada-setup status</code> на компьютере этого процесса и сообщите в
ООО «Телеконтроль».</dd>

<dt>Мнемосхемы не отображаются</dt>
<dd>Если в окне мнемосхемы выводится «Модуль отображения мнемосхем не
установлен», в папке Клиента нет модуля отображения мнемосхем: пакеты Клиента
его пока не содержат — обратитесь в ООО «Телеконтроль» (смотрите
<a href="#displays">Отображение мнемосхем</a>). Иначе проверьте, что файл мнемосхемы есть в папке
<em>%ProgramData%\Telecontrol\SCADA Client</em> или в
<a href="{{ '/server/' | relative_url }}#filesystem">серверной файловой системе</a>.</dd>

<dt>Значения объектов отображаются серым цветом</dt>
<dd>Серый текст значения означает недостоверное значение: например, нет связи
с устройством. Проверьте состояние устройств в панели оборудования
(<em>Дополнительно — Оборудование</em>). Мигающий желтый фон строки означает
другое — у объекта есть неквитированное событие.</dd>

</dl>
