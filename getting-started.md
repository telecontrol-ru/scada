# Начало работы
{:.no_toc}

* TOC
{:toc}

Эта страница описывает версию 2.6, в которой Сервер состоит из отдельных
процессов (смотрите [Состав Сервера]({{ '/architecture/' | relative_url }}#tiers)).

## Системные требования

* ОС Windows 10 и выше (Сервер и Клиент). Установка Сервера под Linux —
  по запросу (смотрите [Установка под Linux](#linux))
* Права администратора Windows для установки и настройки Сервера
* Сеть TCP/IP между компьютерами объекта; Клиенты подключаются к процессу
  `scada-proxy` по порту 2000 (смотрите [Настройка сети](#network))
* Файл лицензии, выданный на нужные процессы Сервера (смотрите [Лицензия](#license))

## Загрузка {#download}

Дистрибутивы публикуются на странице
[выпусков ОИК Телеконтроль на GitHub](https://github.com/alexsmn/scada-client/releases/latest).

**ВНИМАНИЕ:** опубликованный сейчас выпуск 2.5.7 — предыдущего устройства: он
устанавливает Сервер одной службой *Telecontrol SCADA Server* и не содержит
отдельных процессов версии 2.6. Для него действуют прежние правила: служба
*Telecontrol SCADA Server*, аппаратный ключ HASP или Guardant, конфигурация в
папке `%ProgramData%\Telecontrol\SCADA Server\Configuration`.

## Выбор процессов Сервера {#choose}

Сервер версии 2.6 всегда устанавливается из нескольких процессов: процессы
протокольного уровня получают конфигурацию от `scada-config` и не хранят ее
сами, поэтому один такой процесс без `scada-config` работать не может.

Наименьший набор, который создает `scada-setup`:

* `scada-config` — хранит конфигурацию;
* один или несколько процессов протокольного уровня (`scada-modbus`,
  `scada-iec104`, `scada-iec61850`, на Windows также `scada-opc` и
  `scada-vidicon`);
* `scada-filesystem` — без него `scada-setup apply` выводит предупреждение, и
  [серверная файловая система]({{ '/server/' | relative_url }}#filesystem)
  (мнемосхемы на Сервере) недоступна;
* `scada-proxy` — к нему подключаются Клиенты.

Для архива значений и событий добавьте `scada-historian`; без него архива нет.

**Лицензия должна называть каждый из этих процессов**, в том числе
`config`, `filesystem` и `proxy`, а не только процессы протокольного уровня:
процесс, которого нет в лицензии, останавливается сразу после запуска, а
`scada-setup apply` отказывается его устанавливать.

Все процессы можно установить на один компьютер или распределить по
нескольким. **`scada-config`, `scada-proxy`, `scada-historian` и
`scada-filesystem` всегда устанавливаются на один и тот же компьютер —
центральный**; процессы протокольного уровня — на него же или на компьютеры
рядом с оборудованием. Назначение каждого процесса и порядок запуска описаны
в разделе [Состав Сервера]({{ '/architecture/' | relative_url }}#tiers).

## Установка под Windows

Один установщик содержит все процессы Сервера и программу настройки
`scada-setup`. Какие процессы будут работать на компьютере, задаете вы
параметром `--tiers`; лицензия определяет, какие из них разрешены.

**Запускайте `scada-setup` из командной строки с правами администратора и
всегда по полному пути** —
`"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe"`. Установщик не
добавляет эту папку в переменную `PATH`, а программа находит свои шаблоны
относительно пути, по которому ее вызвали: команда `scada-setup`, набранная
без пути, даже из папки `bin`, может не найти их.

**ВНИМАНИЕ: в этой сборке службы, которые регистрирует `scada-setup`, могут
не запускаться** (Windows сообщает об ошибке 1053: служба не ответила на
запрос своевременно). Эта версия `scada-setup` еще не проверялась на объекте
под Windows. Сначала выполните установку на запасном компьютере и убедитесь
командой `status`, что все службы работают; если служба не запускается с
ошибкой 1053, обратитесь в ООО «Телеконтроль». Подробности — в разделе
[Службы могут не запускаться]({{ '/server/' | relative_url }}#services-start-warning).

1. Установите пакет:

   ```bat
   msiexec /i telecontrol-scada-<версия>.msi /qn
   ```

2. Поместите файл лицензии в
   `%ProgramData%\Telecontrol\SCADA Server\license.json`.

3. Решите, какие процессы будут работать на этом компьютере, и
   [запишите параметры компьютера](#host-parameters).

4. Выполните:

   ```bat
   "C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" apply --tiers config,historian,filesystem,iec104,proxy --svc-password <пароль> --root-password <пароль root>
   ```

   В `--tiers` перечислите процессы этого компьютера (в примере — все
   процессы на одном компьютере с протоколом МЭК 60870-5-104). `<пароль>` —
   пароль служебной учетной записи `svc`, через которую процессы подключаются
   друг к другу. Он должен быть одинаковым на всех компьютерах объекта, и
   **сменить его потом нельзя** (смотрите
   [Учетная запись svc]({{ '/server/' | relative_url }}#svc)).
   `<пароль root>` — пароль встроенной учетной записи `root`, смотрите
   [Пароль root](#пароль-root).

Команда `apply` создает для каждого процесса файл параметров
`%ProgramData%\Telecontrol\SCADA Server\<процесс>\server.json` (у
`scada-filesystem` папка называется `filestore`), создает
[сертификат Сервера]({{ '/server/' | relative_url }}#opcua-certificate) в
`C:\Program Files\Telecontrol SCADA\data\Certificates`, если его там еще нет,
создает конфигурационные БД (существующие не перезаписываются), регистрирует
по службе Windows на процесс и запускает их в нужном порядке. Проверить
результат:

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" status
```

В сообщениях `scada-setup` процессы называются *tiers*: строка
`Entitled tiers: …` перечисляет процессы, разрешенные лицензией, а под ней
для каждого процесса выводится состояние его службы (`SERVICE_RUNNING` —
работает).

**ВНИМАНИЕ: пароли `svc` и `root` хранятся открытым текстом.** `apply`
записывает их в параметры служб Windows — в реестр, в значения
`Environment` разделов
`HKLM\SYSTEM\CurrentControlSet\Services\TelecontrolScada<Процесс>`.
Считайте, что их может прочитать любой, кто входит в Windows на этом
компьютере: не допускайте к входу на компьютеры Сервера посторонних и не
устанавливайте Клиент на компьютер Сервера, за которым работают операторы.

**Несколько компьютеров.** Сначала настройте центральный компьютер, затем
компьютеры с процессами протокольного уровня, указав адрес центрального:

```bat
rem Центральный компьютер:
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" apply --tiers config,historian,filesystem,proxy --svc-password <пароль> --root-password <пароль root>
rem Компьютер рядом с оборудованием:
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" apply --tiers modbus,iec104 --central 10.0.0.10 --svc-password <пароль>
```

Процессам протокольного уровня пароль `root` не нужен: учетные записи для них
хранит `scada-config`. На компьютере без `scada-config` параметр `--central`
обязателен. Остальные связи между процессами настраиваются автоматически.
Все команды `scada-setup` описаны в разделе
[Сервер]({{ '/server/' | relative_url }}#scada-setup).

Графический клиент устанавливается на одной или нескольких рабочих станциях.
Сервер и Клиент могут находиться на одном компьютере, если за ним работают
только доверенные пользователи (смотрите предупреждение о паролях выше).

### Параметры компьютера {#host-parameters}

`scada-setup` не запоминает, с какими параметрами его запускали. **Запишите
для каждого компьютера** и храните вместе с паролями:

* `--tiers` — процессы этого компьютера;
* `--central` — адрес центрального компьютера (на компьютере без
  `scada-config`);
* `--advertise` — если вы его задавали;
* `--license` — если файл лицензии лежит не в
  `%ProgramData%\Telecontrol\SCADA Server\license.json`;
* пароль `svc` и пароль `root`.

**Указывайте эти параметры в каждой команде `apply` и `start`** на этом
компьютере (в `apply` — также пароли), в том числе при обновлении и
восстановлении:

* без `--tiers` обе команды берут **все** процессы из лицензии: `apply`
  устанавливает на компьютер процессы, которых на нем быть не должно, а
  `start` прерывается с ошибкой на первом процессе, службы которого на
  компьютере нет, и следующие процессы не запускает;
* без `--central` на компьютере без `scada-config` обе команды отказываются
  работать;
* без `--license` команды ищут лицензию в
  `%ProgramData%\Telecontrol\SCADA Server\license.json`, а `apply` еще и
  записывает этот путь в файлы параметров и службы.

Команды `stop`, `status` и `remove` без `--tiers` действуют на все службы
Сервера, которые есть на компьютере, поэтому им параметры можно не указывать.

**Если `apply` был выполнен без `--tiers`** и установил лишние процессы,
удалите их службы (данные процессов при этом остаются):

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" remove --tiers <лишние процессы через запятую>
```

### Отображение мнемосхем {#displays}

Клиент версии 2.6 отображает мнемосхемы Модус (файлы `.sde` и `.xsde`) сам,
модулем отображения мнемосхем, который должен находиться в папке Клиента рядом
с его исполняемым файлом. Компонент ActiveXeme Клиентом версии 2.6 не
используется. Если модуля нет, в окне мнемосхемы выводится сообщение «Модуль
отображения мнемосхем не установлен» с причиной. Для редактирования мнемосхем
по-прежнему нужен Графический редактор Модус.

## Установка под Linux {#linux}

Процессы Сервера работают под Linux, но в этой версии нет ни пакета для
Linux, ни программы, которая подготовила бы рабочую установку:
`scada-setup` под Linux только создает файлы параметров, не создает
служебную учетную запись `svc` и сертификат и не задает пароли.
**Установка Сервера под Linux выполняется по запросу** — обратитесь в
ООО «Телеконтроль» (mail@telecontrol.ru).

Графический клиент под Linux не поддерживается.

## Лицензия {#license}

Лицензия — подписанный файл `license.json`, в котором перечислены приобретенные
процессы и срок действия. Один и тот же файл кладется на все компьютеры объекта.
Процесс, не названный в лицензии, останавливается сразу после запуска.
Лицензию, срок действия которой еще не начался, не принимают ни процессы, ни
`scada-setup`.

**Срок действия.** Срок окончания лицензии показывает команда
`scada-setup status` (строка `License: … (expires …)`; у истекшей —
`OUTSIDE VALIDITY WINDOW`). Проверяйте его сами: предупреждения об окончании
срока Сервер выдает только системными событиями в Клиенте, за 30 дней до
окончания. После окончания срока процессы продолжают работать, но отклоняют
запросы Клиентов, пока лицензия не будет заменена.

**ВНИМАНИЕ:** с истекшей лицензией `scada-setup` считает разрешенными все
девять процессов: `apply` без `--tiers` установит на компьютер их все.
Указывайте `--tiers` всегда.

**Замена файла лицензии.** Работающие процессы перечитывают файл каждые
5 секунд и подхватывают новую лицензию без перезапуска. Поэтому заменяйте
файл за один шаг: скопируйте новую лицензию в ту же папку под временным
именем, а затем переименуйте ее в `license.json`, заменив старый файл:

```bat
copy new-license.json "%ProgramData%\Telecontrol\SCADA Server\license.new"
move /y "%ProgramData%\Telecontrol\SCADA Server\license.new" "%ProgramData%\Telecontrol\SCADA Server\license.json"
```

**ВНИМАНИЕ:** если в момент проверки файла нет или он записан не полностью
(например, при копировании поверх старого файла), процесс считает, что
лицензии нет, и останавливается. Windows такую службу автоматически не
перезапускает: после замены файла запустите процессы командой `start` с
[параметрами компьютера](#host-parameters):

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" start --tiers <процессы этого компьютера> [--central <адрес>] [--license <путь>]
```

**Добавление процесса.** Замените файл новой лицензией на всех компьютерах.
На компьютере, где будет работать новый процесс, остановите процессы
(`scada-setup stop`) и выполните `scada-setup apply` с полным списком
процессов этого компьютера в `--tiers`, включая новый, и с теми же
остальными параметрами, что и при установке: работающие службы `apply` не
перезапускает (смотрите
[Повторный apply]({{ '/server/' | relative_url }}#reapply)). Запишите новый
список.

Файлы параметров, созданные `scada-setup`, уже содержат
`"license": {"require_gcp_binding": false}`. **Если вы составляете файл
параметров вручную и Сервер работает не в Google Cloud, задайте этот параметр
сами** — иначе процесс не сможет проверить лицензию и не будет обслуживать
запросы. Подробности — в разделе [Лицензирование]({{ '/server/' | relative_url }}#licensing).

## Пароль root

Встроенная учетная запись `root` имеет все права. Ее пароль задается
параметром `--root-password` команды `scada-setup apply` (или переменной
окружения `SCADA_SETUP_ROOT_PASSWORD`). На компьютере, где работает хотя бы
один из процессов `scada-config`, `scada-proxy`, `scada-historian` и
`scada-filesystem`, `apply` без этого пароля не выполняется: у каждого из этих
процессов своя учетная запись `root`, и без заданного пароля она принимала бы
вход с пустым паролем.

`scada-setup` сохраняет пароль в параметрах служб Windows этих процессов, а не
в файлах параметров, и процессы заново записывают его при каждом запуске.
Поэтому:

* **чтобы сменить пароль `root`, остановите процессы (`scada-setup stop`) и
  выполните `scada-setup apply` с новым `--root-password`** — работающие
  процессы `apply` не перезапускает, и без `stop` они продолжали бы
  принимать старый пароль. Пароль, измененный из Клиента, при следующем
  запуске процесса будет заменен заданным в `apply`;
* при каждом повторном `apply`, в том числе при обновлении, указывайте
  действующий пароль `root`.

Подробности — в разделе
[Пароль root]({{ '/server/' | relative_url }}#root-password).

## Настройка сети {#network}

`scada-setup` правила брандмауэра не создает — откройте входящие порты
вручную:

* **для рабочих мест Клиентов** — порт TCP 2000 на центральном компьютере
  (с `scada-proxy`);
* **если процессы установлены на нескольких компьютерах:**
  * на центральном компьютере — порты 4840 (`scada-proxy`) и 4841
    (`scada-config`) для компьютеров с процессами протокольного уровня;
  * на каждом компьютере с процессами протокольного уровня — порт OPC UA
    каждого из его процессов (по таблице ниже) для центрального компьютера:
    к ним подключается `scada-proxy`.

Если все процессы работают на одном компьютере, открывать нужно только
порт 2000.

| Процесс | OPC UA | Клиенты |
|---|:-:|:-:|
| `scada-proxy` | 4840 | 2000 |
| `scada-config` | 4841 | 2001 |
| `scada-historian` | 4842 | 2002 |
| `scada-modbus` | 4843 | 2003 |
| `scada-iec104` | 4844 | 2004 |
| `scada-iec61850` | 4845 | 2005 |
| `scada-filesystem` | 4846 | 2006 |
| `scada-opc` | 4847 | 2007 |
| `scada-vidicon` | 4848 | 2008 |

**ВНИМАНИЕ: порты OPC UA 4840–4848 должны быть доступны только с компьютеров
объекта — в этой версии их защищает только брандмауэр.** Процессы
подключаются друг к другу без шифрования, регистрируются у `scada-proxy` и
`scada-config` без проверки подлинности, а анонимный вход по OPC UA
предлагается всегда. Компьютер, получивший доступ к этим портам, может
подключиться к процессам Сервера или выдать себя за один из них. Если к
Серверу должна подключаться внешняя система OPC UA, разрешите доступ к порту
4840 только с ее адреса (смотрите
[Сервер OPC UA]({{ '/server/' | relative_url }}#opcua)).

Порты 2001–2008 остальных процессов тоже принимают вход пользователей, но
Клиентам не нужны: не открывайте их.

## Подготовка проекта {#project}

**Конфигурация новой установки — демонстрационный проект.** Базы, которые
создает `apply`, — копии демонстрационной конфигурации из состава
установщика: в ней 41 аналоговый и 52 дискретных объекта, сигналы эмуляции,
две включенные связи МЭК 60870-5-104 (одна из них принимает подключения на
порту 2404 этого компьютера), два архива и пользователи «Клиент 1» …
«Клиент 10» и `guest`, которым не заданы пароли. Пока конфигурация не
заменена, процесс `scada-iec104`, если он установлен, занимает порт 2404 и
работает с демонстрационными устройствами. **Перед вводом в работу** либо замените
конфигурацию конфигурацией проекта (ниже), либо удалите в Клиенте
демонстрационные устройства, объекты и пользователей
(смотрите [Проектирование]({{ '/development/' | relative_url }})).

Если у вас есть готовая конфигурационная БД проекта (`configuration.sqlite3`
версии 2.6), положите ее в папки `Configuration` трех процессов, каждый из
которых работает со своей копией: `scada-config` передает конфигурацию
процессам протокольного уровня, `scada-proxy` проверяет по ней имена и пароли
пользователей Клиента, `scada-historian` берет из нее список архивов и их
назначение объектам.

1. Остановите процессы:
   `"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" stop`.
2. Скопируйте файл в папки `config\Configuration`, `proxy\Configuration` и
   `historian\Configuration` внутри
   `%ProgramData%\Telecontrol\SCADA Server`, заменив созданные `apply` базы.
3. Выполните `scada-setup apply` с теми же
   [параметрами компьютера](#host-parameters) и паролями, что и при
   установке. Он сохраняет скопированные базы и добавляет в них служебную
   учетную запись `svc` (идентификатор 100), без которой процессы не смогут
   подключиться друг к другу. **Пользователь проекта с идентификатором 100
   будет заменен учетной записью `svc`.** Если база взята с другого объекта
   версии 2.6, в ней сохранен пароль `svc` того объекта: на этом объекте нужен
   тот же пароль `svc`, иначе процессы не подключатся друг к другу.

Конфигурацию Сервера версии 2.5 переносите командой `scada-setup migrate`:
она переносит и пароли пользователей, которые версия 2.5 хранила в отдельном
файле (смотрите [Обновление с версии 2.5](#upgrade-2-5)).

На каждом рабочем месте скопируйте файлы мнемосхем (`.sde`) в папку
*%ProgramData%\Telecontrol\SCADA Client*. При использовании
[серверной файловой системы]({{ '/server/' | relative_url }}#filesystem)
достаточно загрузить файлы мнемосхем на сервер.

Чтобы ознакомиться с системой без оборудования, задайте объектам
[эмуляцию]({{ '/architecture/' | relative_url }}#эмуляция).

Подробности о создании проекта и настройке оборудования смотрите в разделе [Проектирование]({{ '/development/' | relative_url }}).

## Запуск Сервера

Службы процессов запускаются автоматически вместе с Windows; вход
пользователя в систему не требуется. При сбое процесса Windows перезапускает
его службу (смотрите [Службы Windows]({{ '/server/' | relative_url }}#services)).
Запустить или остановить все процессы компьютера в правильном порядке можно
командами `start` и `stop`; `start` — только с
[параметрами компьютера](#host-parameters):

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" stop
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" start --tiers <процессы этого компьютера> [--central <адрес>] [--license <путь>]
```

Для диагностики процесс может быть запущен в
[консольном режиме]({{ '/server/' | relative_url }}#console).

## Запуск Клиента {#client-start}

Для запуска Клиента используйте пиктограмму *Клиент* на рабочем столе или из меню *Пуск — ОИК Телеконтроль*. При этом будут запрошены реквизиты пользователя ОИК для подключения к Серверу:

![]({{ '/img/client-login.png' | relative_url }})

При первом запуске войдите как *root* с паролем, заданным параметром
`--root-password` при установке.

Строка *Сервер* состоит из двух полей. Слева — список типов сервера (он
показывается, только если Клиент поддерживает больше одного типа): выберите
**«Телеконтроль»**.

> **Внимание.** Тип «OPC UA» подключает Клиент по протоколу OPC UA. В текущей
> версии Клиент, подключённый по этому типу, после потери связи **не
> переподключается сам**: восстановите связь, перезапустив Клиент. Для работы с Сервером ОИК
> используйте тип «Телеконтроль».

Справа введите имя или адрес IP компьютера, где работает процесс
`scada-proxy`, если он отличается от текущего. Иначе поле оставьте
пустым.

Раскрывающийся раздел «Защита и сертификаты» (режим защиты, сертификат и
закрытый ключ клиента) появляется только для типа «OPC UA»; для типа
«Телеконтроль» заполнять его не нужно.

При установленном флаге *Входить автоматически в следующий раз* программа будет использовать указанные реквизиты при каждом последующем запуске без отображения окна входа. Чтобы в Windows один раз войти с другими реквизитами, удерживайте *Ctrl* при запуске Клиента; в других ОС такой возможности нет.

## Первые шаги после входа

**Пока конфигурация не заменена, вы видите демонстрационный проект**
(смотрите [Подготовка проекта](#project)): объекты, устройства и
пользователи «Клиент 1» … «Клиент 10» и `guest` в нем — демонстрационные.
Удалите их или замените конфигурацию до ввода системы в работу.

После входа в систему:

1. **Откройте панель объектов** — меню *Дополнительно — Объекты*. В панели отображается дерево объектов с текущими значениями. Двойной клик по объекту открывает его график.

2. **Просмотрите мнемосхемы** — меню *Мнемосхема*. Выберите доступную схему из списка.

3. **Проверьте состояние оборудования** — меню *Дополнительно — Оборудование*. Иконки слева от устройств показывают состояние связи.

4. **Создайте пользователей** — меню *Дополнительно — Пользователи*. Создайте учетные записи для операторов и работайте под ними, а не под *root*. Смотрите [Конфигурирование пользователей]({{ '/dev/users/' | relative_url }}). Создав пользователя, сразу проверьте, что под ним можно войти; если нельзя, обратитесь в ООО «Телеконтроль».

   **ВНИМАНИЕ:** в списке пользователей есть служебная учетная запись `svc`.
   Не изменяйте и не удаляйте ее: через нее процессы Сервера подключаются
   друг к другу (смотрите
   [Учетная запись svc]({{ '/server/' | relative_url }}#svc)).

Далее смотрите описание [Клиента]({{ '/client/' | relative_url }}).

## Обновление

Этот порядок — для обновления версии 2.6 и новее. Сервер версии 2.5 и ранее
был одним процессом с одной службой, и его данные нужно перенести в процессы
версии 2.6 — смотрите [ниже](#upgrade-2-5).

Перед обновлением сделайте резервную копию — смотрите
[Резервное копирование]({{ '/server/' | relative_url }}#backup).
Затем на каждом компьютере в командной строке с правами администратора:

```bat
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" stop
msiexec /i telecontrol-scada-<новая версия>.msi /qn
"C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" apply --tiers <процессы этого компьютера> [--central <адрес>] [--advertise <адрес>] [--license <путь>] --svc-password <пароль> --root-password <пароль root>
```

Повторите в `apply` те же [параметры компьютера](#host-parameters), что и
при установке, и тот же пароль `svc`. Установщик заменяет только исполняемые
файлы; `apply` заново создает файлы параметров (изменения, внесенные в них
вручную, теряются) и не трогает данные. На компьютерах только с процессами
протокольного уровня `--root-password` можно не указывать.

### Обновление с версии 2.5 {#upgrade-2-5}

Сервер версии 2.5 работал одной службой *Telecontrol SCADA Server* и
использовал аппаратный ключ. Установщик версии 2.6 заменяет программу версии
2.5, поэтому **проверьте план перехода до установки 2.6**: то, что мешает
переходу, исправляется только в версии 2.5.

**ВНИМАНИЕ: не выполняйте `migrate --execute` на рабочем объекте версии
2.5, пока не убедитесь, что службы 2.6 запускаются.** В этой сборке службы,
которые регистрирует `scada-setup`, могут не запускаться (ошибка 1053), а
`migrate --execute` удаляет службу версии 2.5. Сначала проверьте `apply` и
`start` на запасном компьютере (смотрите
[Службы могут не запускаться]({{ '/server/' | relative_url }}#services-start-warning));
если служба не запускается с ошибкой 1053, обратитесь в
ООО «Телеконтроль». Как вернуться к версии 2.5, описано в разделе
[Возврат к версии 2.5]({{ '/server/' | relative_url }}#rollback-2-5).

На компьютере, где работал Сервер 2.5:

1. Получите лицензию версии 2.6 и положите ее в
   `%ProgramData%\Telecontrol\SCADA Server\license.json`.
2. Сделайте резервную копию папки `%ProgramData%\Telecontrol\SCADA Server`.
3. Распакуйте пакет 2.6 во временную папку, не устанавливая его, и выполните
   распакованной программой `scada-setup migrate` — она ничего не меняет и
   выводит план. Исправьте в версии 2.5 то, что мешает переходу, и повторите
   проверку. Порядок описан в разделе
   [Переход с версии 2.5]({{ '/server/' | relative_url }}#upgrade-2-5).
4. Установите пакет версии 2.6 (`msiexec /i telecontrol-scada-<версия>.msi /qn`).
5. В командной строке с правами администратора выполните:

   ```bat
   "C:\Program Files\Telecontrol SCADA\bin\scada-setup.exe" migrate --execute --tiers config,historian,filesystem,iec104,proxy --svc-password <пароль> --root-password <пароль root>
   ```

   В `--tiers` перечислите процессы этого компьютера: `config`,
   `historian`, `filesystem`, `proxy` и **процесс протокольного уровня для
   каждого протокола**, по которому работают устройства версии 2.5 (в
   примере — `iec104`; для MODBUS — `modbus`, для МЭК 61850 — `iec61850`).
   Команда не предупреждает, если такой процесс пропущен, — данные с
   устройств этого протокола тогда не собираются.

   Команда удаляет старую службу, копирует конфигурацию, пользователей с
   паролями, архивы и файлы мнемосхем в папки процессов 2.6 и запускает их,
   как `apply` (в том числе создает сертификат Сервера). Пароль `root` версии
   2.5 при этом заменяется паролем из `--root-password` (смотрите
   [Пароль root](#пароль-root)). **Если команда завершилась ошибкой после
   копирования, не повторяйте `migrate`** — завершите переход командами
   `stop` и `apply` с теми же `--tiers` и паролями (смотрите
   [Переход с версии 2.5]({{ '/server/' | relative_url }}#upgrade-2-5)).
6. Установите Клиент версии 2.6 на **каждом** рабочем месте (смотрите
   [Отображение мнемосхем](#displays)): работа Клиента версии 2.5 с
   Сервером 2.6 не проверялась.
7. Проверьте работу Клиентом.

Старые папки `Configuration`, `History` и `FileSystem` не изменяются и не
удаляются.

### Удаление {#uninstall}

Перед удалением программы удалите службы командой
`scada-setup remove --tiers <процессы этого компьютера>`: установщик не
удаляет ни службы, ни их параметры в реестре с паролями `svc` и `root`, ни
папки данных и закрытый ключ сертификата. Порядок описан в разделе
[Удаление Сервера]({{ '/server/' | relative_url }}#uninstall).

## Устранение неполадок

Команды `scada-setup`, упомянутые ниже, выполняйте по полному пути из
командной строки с правами администратора — в том числе `status`.

<dl>

<dt>Служба не запускается, Windows сообщает об ошибке 1053</dt>
<dd>В этой сборке службы, зарегистрированные <code>scada-setup</code>, могут
не запускаться. Обратитесь в ООО «Телеконтроль»; для диагностики процесс
можно запустить в
<a href="{{ '/server/' | relative_url }}#console">консольном режиме</a>.
Смотрите
<a href="{{ '/server/' | relative_url }}#services-start-warning">Службы могут не запускаться</a>.</dd>

<dt>Новый пароль <code>root</code> или другие параметры <code>apply</code> не действуют</dt>
<dd><code>apply</code> не перезапускает работающие службы. Выполните
<code>scada-setup stop</code>, а затем <code>apply</code> (смотрите
<a href="{{ '/server/' | relative_url }}#reapply">Повторный apply</a>).</dd>

<dt>Клиент не может подключиться к Серверу</dt>
<dd>Убедитесь, что служба <em>Telecontrol SCADA Proxy</em> запущена
(<code>scada-setup status</code> на ее компьютере). Проверьте, что порт 2000
разрешен в брандмауэре и доступен по сети.</dd>

<dt>Процесс Сервера останавливается сразу после запуска</dt>
<dd>Нет действительного файла лицензии или лицензия не включает этот процесс,
либо удален один из файлов <a href="{{ '/server/' | relative_url }}#opcua-certificate">сертификата Сервера</a>
(в журнале — <code>Can't open file</code>; <code>scada-setup apply</code> в этом
случае сообщает, какого файла не хватает). Причина записывается в
<a href="{{ '/server/' | relative_url }}#logging">журнал процесса</a>. Смотрите
<a href="{{ '/server/' | relative_url }}#licensing">Лицензирование</a>.</dd>

<dt>Служба останавливается или постоянно перезапускается, а в журнале ничего нет</dt>
<dd>Скорее всего, ошибка в файле параметров <code>server.json</code>
(например, после правки вручную). О ней процесс сообщает до того, как начинает
писать журнал, — только на экран. Запустите процесс в
<a href="{{ '/server/' | relative_url }}#console">консольном режиме</a> и
прочитайте сообщение.</dd>

<dt>Процессы протокольного уровня не получают конфигурацию</dt>
<dd>Если в журнале процесса протокольного уровня есть
<code>Bad_UserAccessDenied</code>, пароль <code>svc</code> на этом компьютере
не совпадает с паролем центрального компьютера. Выполните на нем
<code>scada-setup stop</code>, а затем <code>apply</code> с первоначальным
паролем <code>svc</code> (смотрите
<a href="{{ '/server/' | relative_url }}#svc">Учетная запись svc</a>).</dd>

<dt>Все процессы остановились после замены файла лицензии</dt>
<dd>Файл был недоступен или записан не полностью в момент проверки. Положите
действительный файл (смотрите <a href="#license">Замена файла лицензии</a>) и
выполните <code>scada-setup start</code> с
<a href="#host-parameters">параметрами компьютера</a>.</dd>

<dt><code>scada-setup start</code> прерывается с ошибкой</dt>
<dd>Команда выполнена без <code>--tiers</code> (или без
<code>--central</code>) и пытается запустить процесс, службы которого на
компьютере нет. Повторите ее с <a href="#host-parameters">параметрами
компьютера</a>.</dd>

<dt>Процесс работает, но отклоняет запросы</dt>
<dd>Лицензия не проверена или истекла (срок — в выводе
<code>scada-setup status</code>). Вне Google Cloud проверьте, что задан
<code>"license": {"require_gcp_binding": false}</code>; при истекшей лицензии
замените файл — перезапуск не нужен.</dd>

<dt>Значения перестали записываться в архив</dt>
<dd>После перезапуска службы процесса протокольного уровня (например,
<em>Telecontrol SCADA IEC 104</em>), в том числе автоматического после сбоя,
запись в архив значений его объектов прекращается. Перезапустите службу
<em>Telecontrol SCADA Historian</em>. Смотрите
<a href="{{ '/server/' | relative_url }}#monitoring">Наблюдение за работой</a>.</dd>

<dt>Мнемосхемы не отображаются</dt>
<dd>Если в окне мнемосхемы выводится «Модуль отображения мнемосхем не
установлен», в папке Клиента нет модуля отображения мнемосхем — обратитесь в
ООО «Телеконтроль». Иначе проверьте, что файл мнемосхемы есть в папке
<em>%ProgramData%\Telecontrol\SCADA Client</em> или в
<a href="{{ '/server/' | relative_url }}#filesystem">серверной файловой системе</a>.</dd>

<dt>Значения объектов отображаются серым цветом</dt>
<dd>Серый текст значения означает недостоверное значение: например, нет связи
с устройством. Проверьте состояние устройств в панели оборудования
(<em>Дополнительно — Оборудование</em>). Мигающий желтый фон строки означает
другое — у объекта есть неквитированное событие.</dd>

</dl>
